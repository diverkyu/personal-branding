## 1. 한 줄 콘셉트

> **Dive deeper. Create beyond.** — 바다에서 시작해 이야기로 이어지는, 규강의 공간.

기존 시안의 슬로건과 시각 언어(딥블루 `#071e29`, 라임 `#d6f48a`, 페이퍼 `#f4f4ec`, 큰 영문 타이포, 수중 일러스트)를 계승한다. 톤앤매너와 카피는 기존 시안에서 선별된 문구를 이어 가며, 기준은 [§7](#7-톤앤매너와-카피-가이드)에 정리했다. 사이트는 "포트폴리오 전시"에서 **"찾아와서 행동하는 곳"**으로 바뀐다. 방문자가 투어에 문의하고, 장비를 참고하고, 규강의 이야기를 읽는 것이 핵심 흐름이다.

## 2. 방문자 여정

| 여정 | 흐름 | 목표 행동 |
| --- | --- | --- |
| 투어 참가 | 인스타그램 → 홈의 "진행 예정 투어" → 투어 상세 → 후기 확인 → 신청 폼 | 투어 신청/문의 제출 |
| 신뢰 확인 | 투어 상세·홈에서 후기 발견 → 후기 전체 보기 | 투어 상세로 되돌아가 신청 |
| 장비 탐색 | Freediving → 장비 → 카테고리 → 상세 | 구매 링크 클릭 또는 장비 문의 |
| 사람 알기 | 홈 최신 스토리 → 스토리 목록 → 글 | 글 읽기, 인스타그램 팔로우 |

## 3. 사이트 구조

```text
/                          홈
/about                     1. 규강 소개
/story                     2. 스토리 목록 (규강이 생각하는 것들)
  /story/[slug]            글 상세
/freediving                3. 프리다이빙 허브 (투어·장비·후기 입구)
  /freediving/tours        투어 목록 (진행 예정 / 지난 투어)
  /freediving/tours/[slug] 투어 상세 + 신청 폼 + 이 투어의 후기
  /freediving/equipment    장비 목록 (카테고리 필터)
  /freediving/equipment/[slug]  장비 상세
  /freediving/reviews      수강 후기 전체 (§5 참고)
/contact                   4. 일반 문의
/admin                     CMS 어드민 (비공개)
```

내비게이션 (확정 순서): `KYU　|　About　Story　Freediving　|　Contact ↗` (Freediving은 드롭다운으로 투어·장비·후기). 먼저 규강이 누구인지(About), 규강이 생각하는 것(Story)을 보여 준 뒤 프리다이빙 활동(Freediving)으로 이어지는 순서다. Phase 2에서 `Films`는 Freediving 뒤, Contact 앞에 추가된다.

## 4. 페이지별 콘셉트

각 페이지의 문구 톤과 고정 카피 시안은 [§7.3, §7.4](#73-페이지별-톤)를 따른다.

**홈** — 메뉴 순서와 같은 흐름. 슬로건 히어로(수중 일러스트 유지)와 규강 소개 요약(About) → 최신 스토리 3건 → 진행 예정 투어 1~2건(모집 상태 뱃지)과 대표 후기 3건 → 인스타그램 링크. 진행 예정 투어가 없으면 "다음 투어 소식 받기"로 대체한다.

**About** — 규강 소개 페이지이자 사이트의 첫 메뉴. 바다에서의 경험과 창작을 한 사람의 이야기로 연결한다(기존 시안의 "서로 다른 두 세계. 하나의 호기심." 계승). 실제 이력·자격은 규강이 확인한 것만 기재한다.

**투어 목록/상세** — 목록은 위에 "진행 예정", 아래에 "지난 투어 아카이브". 상세는 대표 이미지/영상 → 핵심 정보(일정·장소·모집 상태·정원) → 상세 설명 → 이 투어의 후기 → 신청 폼 순서이고, 모바일에서는 하단에 "신청하기" 고정 버튼을 둔다. 지난 투어 상세는 신청 폼 대신 후기·갤러리·스케치 영상이 중심이다.

**장비** — 카드 그리드(썸네일·이름·한 줄 추천 이유), 카테고리 필터. 상세는 규강의 추천 이유를 먼저 보여주고 특징을 뒤에 둔다. 하단 버튼은 장비별 설정에 따라 "구매처 보기 ↗" 또는 "문의하기"이고, 없으면 숨긴다. 제휴 링크는 고지 문구를 같이 표시한다.

**스토리** — 일기/블로그 톤. 큰 대표 이미지, 읽기 좋은 본문 폭, 이미지 중심 에디토리얼 레이아웃. 글 하단에는 이전/다음 글과 인스타그램 링크 정도만 두고, **후기나 투어 광고는 넣지 않는다.** 읽는 경험을 지키기 위함이다.

## 5. 수강 후기 UX 배치 (2026-11-07 C안 확정)

### 5.1 비교

| 안 | 장점 | 단점 |
| --- | --- | --- |
| A. 독립 페이지만 | 구현 단순, 후기 모음 한눈에 | 방문자가 일부러 찾아가야 해서 **신뢰가 필요한 순간(신청 직전)에 노출되지 않음** |
| B. 각 페이지에 녹이기만 | 맥락 속에서 신뢰 형성 | 후기 전체를 볼 곳이 없고, 중복 입력·관리 부담, SEO 단일 랜딩이 없음 |
| **C. 하이브리드 (제안)** | 신뢰 순간에 노출 + 전체 보기 + 한 번 입력 | A+B의 구현을 모두 필요로 함(재사용 컴포넌트로 비용 절감) |

### 5.2 확정: C안 — "한 번 입력, 맥락별 노출, 전체는 한 곳에"

**데이터 흐름**
- 후기는 `Review` 한 곳에서만 입력한다. 투어 연결(선택)과 "대표 후기" 체크로 노출 위치가 결정된다.
- 동일한 `ReviewCard`/`ReviewList` 컴포넌트를 모든 곳에서 재사용한다.

**노출 위치**

| 위치 | 보여주는 후기 | 이유 |
| --- | --- | --- |
| 투어 상세 | 그 투어에 연결된 후기. 없으면 대표 후기 | 신청 직전의 가장 강한 신뢰 신호. 지난 투어는 후기가 핵심 콘텐츠 |
| 홈 | 대표 후기 3건 + "후기 전체 보기" | 첫 방문자의 신뢰 형성 |
| `/freediving/reviews` | 전체, 투어별 필터 | 모든 후기를 볼 수 있는 단일 랜딩 (SEO·공유 링크) |
| 스토리 | **노출 안 함** | 일기 톤 유지 (규강의 개인 공간) |
| 장비 | **노출 안 함** | 후기는 강습에 대한 것이라 맥락이 다름 |
| 푸터 | 후기 전체 링크만 | 사이트 전역 접근 경로 |

**근거**: (1) 후기의 가치는 "결정 직전"에 있다. (2) 1인 운영이라 입력 지점이 하나여야 한다. (3) 독립 페이지는 신뢰 콘텐츠를 검색·AI 인용 대상으로 만들어 준다. 기존 컨셉안(PRODUCT-CONCEPT)의 "후기는 수업 가까이에 둔다"는 방향과도 일치한다.

**열린 점**: 후기 작성자 표기 방식(실명/이니셜/닉네임)과 공개 동의. 평점은 쓸지 규강이 결정한다. 평점이 없는 편이 인용형 후기로서 더 신뢰를 준다는 점을 참고하라.

## 6. 어드민 콘셉트 — "콤팩트"

- 좌측 메뉴 6개: 대시보드 / 스토리 / 투어 / 장비 / 후기 / 미디어(+설정)
- **대시보드**: 오늘 해야 할 일만. 신규 투어 신청 N건, 임시저장 글 N건, 모집중 투어 N건
- **목록 → 편집** 2단계 구조로 통일. 모든 목록에 상태 필터와 검색
- **스토리 편집기**: 글 쓰는 데 집중하는 한 화면. 자동 임시저장, 이미지 붙여넣기/끌어놓기, 발행 버튼
- **투어 편집기**: 기본 정보 / 설명 / 미디어 / 후기 연결 탭. "신청" 탭에서 해당 투어의 접수 내역을 바로 확인
- **모바일 대응**: 신청 확인과 상태 변경이 폰에서 가능해야 한다
- 용어는 한국어로, 비개발자도 쓸 수 있는 문구로 표시한다

## 7. 톤앤매너와 카피 가이드

**기준 자료**: 시안 v0.1.0의 [COPY.md](../COPY.md)·[DESIGN.md](../DESIGN.md)와 리뉴얼 컨셉안 [PRODUCT-CONCEPT.md](../PRODUCT-CONCEPT.md). 기존 카피는 규강을 나타내는 여러 단어 조합 중에서 골라낸 것이다. 그래서 두 가지를 원칙으로 한다.

1. **기존에 확정된 카피는 바꾸지 않는다.** 새 페이지에서도 그대로 이어 쓴다.
2. **새 카피는 아래의 어휘·리듬·문체에서 파생한다.** 규강 승인 전까지는 모두 "시안"이다. (§7.4)

### 7.1 브랜드 핵심어와 어휘

| 구분 | 내용 | 출처 |
| --- | --- | --- |
| 핵심어 | **깊이 / 상상 / 호기심** | DESIGN §1 |
| 슬로건 | Dive deeper. Create beyond. | 히어로 |
| 한국어 헤드라인 | 바다에서는 더 깊이, 상상 속에서는 더 멀리. | 히어로 |
| 반복되는 어휘 | 한 호흡, 고요함, 물속, 바다, 경계 너머, 탐험, 새로운 세계, 가능성, 두 가지 언어, 함께 | COPY 전반 |
| 감각의 방향 | 고요한 바다 + 자유로운 상상. 과도한 장식 없이 여백으로 | DESIGN §8 |

새 카피에는 위 어휘를 우선 쓰고, 이 결을 벗어나는 낯선 비유·유행어는 쓰지 않는다.

### 7.2 문체 규칙

| 규칙 | 기존 카피의 예 | 적용 |
| --- | --- | --- |
| **짧은 대구와 반복**으로 리듬을 만든다 | "바다에서는 더 깊이, 상상 속에서는 더 멀리." / "서로 다른 두 세계. 하나의 호기심." | 페이지 헤드라인은 두 박자로 |
| **마침표로 끊고 줄바꿈으로 숨을 쉰다** | "다음 탐험은,\n함께." | 헤드라인은 2줄 이내, 의미 단위로 줄바꿈 |
| 소개·선언은 **1인칭 "저" + 합쇼체** | "프리다이빙 강사이자 AI 크리에이터, 이동규입니다." / "저는 경계 너머의 가능성을 탐험합니다." | About, Story, 장비 추천 이유 |
| 초대·행동 유도는 **"~주세요 / ~보세요"** | "당신의 이야기를 들려주세요." / "Instagram에서 만나보세요." | Contact, 폼 안내 |
| 시스템 안내는 **담백한 합쇼체** | "이메일 주소를 복사했습니다." | 접수·오류·빈 상태 문구 |
| 제목은 **감각적인 명사구 또는 짧은 서술** | "처음 물에 들어가는 날." / "물속에서 떠올린 이야기." | 투어·후기·스토리 섹션 제목 |
| **영문은 슬로건·라벨·번호 전용**, 설명은 한글 | `01 / ABOUT KYU`, `02 / TWO WORLDS, ONE KYU` | 섹션 라벨은 작은 대문자 + 번호 |
| 버튼은 **행동이 분명한 한글 + ↗** | "나의 세계 둘러보기 ↗" | 외부/이동 링크에 ↗, 복사에 ⧉ |
| 기호는 **기존에 쓴 것만** | ↗ ↓ ∞ ≈ ✳ ⧉ | 느낌표·이모지는 기존 시안에 없으므로 쓰지 않음 |

### 7.3 페이지별 톤

| 페이지 | 톤 | 기존에서 그대로 이어 쓸 것 | 새로 쓸 때 주의 |
| --- | --- | --- | --- |
| 홈 | 선언적. 큰 타이포 | 슬로건, 한국어 헤드라인, 소개문, 구분 띠 | 히어로 카피는 수정하지 않는다 |
| About `01 / ABOUT KYU` | 차분한 1인칭 | "서로 다른 두 세계. 하나의 호기심.", 서명 "이동규 aka. KYU" | 이력·자격은 규강이 확인한 것만 |
| Story `02 / STORY` | 솔직하고 조용한 1인칭. 광고하지 않는다 | 물속의 고요함, 경계 너머 같은 감각 어휘 | 글 안에 투어·후기 광고를 넣지 않는다 (§5) |
| Freediving `03 / FREEDIVING` | 안심되고 차분함. 권유는 부드럽게 | "처음 물에 들어가는 날.", "바다를 만나고, 호흡에 집중하고, 물속에서 새로운 감각을 발견하는 시간." | 모집·마감 등 상태는 사실만. 재촉·희소성 문구 금지 |
| 장비 | 규강의 목소리로 이유를 설명 | 1인칭 "저" | 실제 사용·검증하지 않은 장비를 "써 봤다"고 쓰지 않는다 |
| 후기 | **원문 보존** | 블루페블 후기 4건의 원문 | 요약·윤문·평점 가공을 하지 않는다 |
| Contact `04 / LET’S CONNECT` | 따뜻한 초대 | "다음 탐험은, 함께.", "당신의 이야기를 들려주세요." | 폼 항목 이름은 짧고 담백하게 |

섹션 번호는 새 메뉴 순서(About 01 → Story 02 → Freediving 03 → Contact 04)와 맞춘 **제안**이다. 기존 시안은 04가 Contact였으므로 번호 체계는 그대로 이어진다.

| 투어 접수 완료 | "문의가 접수되었습니다. 확인 후 남겨주신 연락처로 답변드리겠습니다." | 시스템 안내 문체 |
| 투어 전송 실패 | "전송하지 못했습니다. 잠시 후 다시 시도하거나 이메일로 문의해주세요." | 기존 복사 실패 문구의 결 |
| 예정 투어 없음 | "다음 투어를 준비하고 있습니다. 소식이 궁금하시면 문의를 남겨주세요." | 부드러운 권유 |
| 후기 섹션 제목 | "함께 물에 들어간 사람들의 이야기." | 제목 명사구 + "함께" |
| 장비 섹션 제목 | "제가 추천하는 장비." | 1인칭, 과장 없음 |
| 제휴 링크 고지 | "이 링크로 구매하시면 수수료를 받을 수 있습니다." | 제휴가 있을 때만 노출 |

### 7.5 지킬 것

- 확정된 기존 카피(COPY.md)는 수정하지 않고, 새 카피는 시안 단계를 거쳐 규강 승인 후 반영한다
- 실제 이력·자격·수상·고객·수치는 **규강이 확인한 것만** 쓴다. 없는 정보를 채우지 않는다
- 투어는 "신청" 대신 **"예약 문의"**로 표기해 결제·확정과의 혼동을 막는다 (결제 기능이 없으므로)
- 후기는 원문을 보존하고, 작성자 표기는 동의받은 방식만 쓴다
- 고정 문구는 코드에 박지 않고 사이트 설정(공통 카피)에서 관리한다 (PRD W-7)

### 7.6 시각 톤과의 연결

공개 페이지는 기존 디자인 토큰을 재사용한다: 딥블루 `#071e29`, 라임 `#d6f48a`, 페이퍼 `#f4f4ec`, DM Sans / Noto Sans KR. 어두운 섹션과 밝은 섹션을 교차해 읽는 리듬을 유지하고, 장식보다 여백으로 고요함을 표현한다.

- 홈·Freediving 허브: 딥블루 중심 (바다)
- Story: 페이퍼 배경, 읽기 좋은 본문 폭 (일기장의 차분함)
- 후기·장비 카드: 페이퍼 위의 얇은 구분선, 라임은 행동 버튼과 강조에만
- 어드민은 이 톤을 따르지 않아도 되며 기능성을 우선한다 (한국어 담백체는 유지)

토큰과 컴포넌트 명세는 [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md)에 정리한다.

### 7.7 확인이 필요한 용어

- "예약 문의"(이 문서) 대 "수업 일정 문의"(PRODUCT-CONCEPT의 Dive 버튼) 대 "프리다이빙 문의"(시안 v0.1.0): 하나로 통일할지 규강이 정한다
- PRODUCT-CONCEPT의 `Dive`와 이 문서의 `Freediving`: 메뉴에 어느 이름을 쓸지 결정 필요 (PRD §11)

### 7.8 사용 리소스와 라이선스 (2026-11-08 갱신)

사이트에서 상품을 판매하는 마켓 기능도 고려하므로, **상업 이용이 명확한 오픈소스만** 쓰고 IP 이슈가 있을 만한 요소는 뺀다.

| 리소스 | 라이선스 | 상업 이용 | 확인 방법 | 비고 |
| --- | --- | --- | --- | --- |
| DM Sans | SIL OFL 1.1 (Colophon Foundry) | 가능 | Google Fonts 저장소의 `METADATA.pb`, `OFL.txt` | 임베드·재배포 가능. 자체 호스팅 시 저작권 고지와 라이선스 사본을 함께 둔다 |
| Noto Sans KR | SIL OFL 1.1 (Google, Adobe) | 가능 | 위와 동일 | 수정본을 만들면 Reserved Font Name 'Source'를 쓸 수 없다 |
| **Lora** (`beyond.` 강조, 서명) | SIL OFL 1.1 (Cyreal) | 가능 | Google Fonts 저장소의 `METADATA.pb`, `OFL.txt` | **Georgia를 대체** (2026-11-08 결정). 한글은 포함되지 않아 한글 서명은 Noto Sans KR로 표시된다 |
| **Lucide 아이콘** | ISC (일부 아이콘은 Feather 유래 MIT) | 가능 | 저장소 `LICENSE` | **글자 기호(↗ ⧉ ☰)를 대체**. 사용 시 저작권·라이선스 고지를 유지한다 ([DESIGN-SYSTEM §8](DESIGN-SYSTEM.md)) |
| 수중 일러스트(SVG), 그라디언트 썸네일 | 직접 제작 | 가능 | 코드로 직접 작성. 외부 이미지 없음 | 실제 사진·영상은 규강 소유 또는 사용 허락 확인 후 사용 |
| 기호 `∞` | 유니코드 문자 | 가능 | 폰트 파일이 아닌 문자 | 구분 띠의 텍스트 장식에만 사용 |
| `KYU` 로고 | **상표 등록 미확인** | 확인 필요 | 기존 README(v0.1.0)에 "등록 여부 미검증"으로 기록됨 | **`®`는 제거** (2026-11-08). 아래 상표 확인 참고 |

**제거·대체한 것**: Georgia(상용 폰트), 글자 기호 `↗ ⧉ ☰ ↑ ↓ ≈ ✳`, 로고의 `®`.

**상표 확인 (마켓 개시 전)**
1. `®`는 등록된 상표에만 쓰는 표시다. 등록 전에는 쓰지 않는다. (허위 표시를 금지하는 규정이 있는 것으로 알고 있으나 정확한 조문은 전문가 확인)
2. 로고·이름 자체를 빼야 하는 것은 아니다. 다만 `KYU`는 짧은 이름이라 같거나 비슷한 상표가 이미 있을 수 있다.
3. KIPRIS(특허정보검색서비스)에서 `KYU`와 유사 상표를 판매 예정 상품류(예: 의류, 스포츠용품, 소매업, 교육) 기준으로 검색한다.
4. 검색 절차와 기록 양식은 [TRADEMARK-CHECK.md](TRADEMARK-CHECK.md)에 있다. 충돌이 없으면 출원을 검토한다 (선출원주의라 빠를수록 유리). 변리사 상담을 권한다.
5. 등록이 완료되면 그때 `®`를 다시 붙인다.

**남은 사항**
- 글꼴은 **자체 호스팅**을 권장한다 (OFL 허용). Google CDN을 쓰면 방문자 접속 정보가 Google 서버로 전달된다. 호스팅 결정 후 확정.
- 후기·사진·영상·판매 상품 이미지는 작성자·촬영자 동의가 필요하다 (PRD §12.3).
- 법률 검토가 아니라 라이선스 문서 확인이다.

## 8. Phase 1 개발 실행 계획

| 순서 | 산출물 | 결정/확인 필요 |
| --- | --- | --- |
| 0 | 스타터 키트 검토 완료(PRD §10) → 스택 확정 | 호스팅, 저장소 구조(PRD §11) |
| 1 | DB 스키마·데이터 구조 제안서 (PRD §6을 구체화) | 후기 배치 구조 승인, 폼 항목 확정 |
| 2 | 어드민 설계서 + 구현 (인증 → 미디어 → 스토리 → 투어/신청 → 장비 → 후기) | 스토리 에디터 선택 |
| 3 | 공개 사이트 구현 (공통 레이아웃 → 스토리 → 투어 → 장비 → 후기 + 홈 연동) | 디자인 시안 방향 |
| 4 | 콘텐츠 이관, SEO/GEO 점검 | 후기 동의 |
| 5 | **사이트 게시**: 공개 전 점검 → 가칭 도메인 연결 → 운영 시작 | 호스팅 방식(열린 결정), 도메인 상태 |

확정된 것은 "사이트를 공개한다"는 목표이고, 호스팅 방식은 나중에 함께 정한다(Vercel은 후보 중 하나). 배포 환경은 기능 개발 전에 먼저 만든다(빈 앱 배포 → PR마다 미리보기로 규강이 확인 → 병합). 단계별 로드맵, 게시 전 체크리스트, 도메인 변경 절차는 [PRD §12](PRD.md#12-배포게시-로드맵)에 있다. 도메인 `diverkyu.com`은 가칭이므로 사이트 주소는 환경변수 한 곳에서만 정의한다.
