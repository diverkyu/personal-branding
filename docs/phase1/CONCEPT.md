## 1. 한 줄 콘셉트

> **Dive deeper. Create beyond.** — 바다에서 시작해 이야기로 이어지는, 규강의 공간.

기존 시안의 슬로건과 시각 언어(딥블루 `#071e29`, 라임 `#d6f48a`, 페이퍼 `#f4f4ec`, 큰 영문 타이포, 수중 일러스트)를 계승한다. 사이트는 "포트폴리오 전시"에서 **"찾아와서 행동하는 곳"**으로 바뀐다. 방문자가 투어에 문의하고, 장비를 참고하고, 규강의 이야기를 읽는 것이 핵심 흐름이다.

## 2. 방문자 여정

| 여정 | 흐름 | 목표 행동 |
| --- | --- | --- |
| 투어 참가 | 인스타그램 → 홈의 "진행 예정 투어" → 투어 상세 → 후기 확인 → 신청 폼 | 투어 신청/문의 제출 |
| 신뢰 확인 | 투어 상세·홈에서 후기 발견 → 후기 전체 보기 | 투어 상세로 되돌아가 신청 |
| 장비 탐색 | Freediving → 장비 → 카테고리 → 상세 | 구매 링크 클릭 또는 장비 문의 |
| 사람 알기 | 홈 최신 스토리 → 스토리 목록 → 글 | 글 읽기, 인스타그램 팔로우 |

## 3. 사이트 구조

```text
/                          홈
/about                     1. 규강 소개
/story                     2. 스토리 목록 (규강이 생각하는 것들)
  /story/[slug]            글 상세
/freediving                3. 프리다이빙 허브 (투어·장비·후기 입구)
  /freediving/tours        투어 목록 (진행 예정 / 지난 투어)
  /freediving/tours/[slug] 투어 상세 + 신청 폼 + 이 투어의 후기
  /freediving/equipment    장비 목록 (카테고리 필터)
  /freediving/equipment/[slug]  장비 상세
  /freediving/reviews      수강 후기 전체 (§5 참고)
/contact                   4. 일반 문의
/admin                     CMS 어드민 (비공개)
```

내비게이션 (확정 순서): `KYU®　|　About　Story　Freediving　|　Contact ↗` (Freediving은 드롭다운으로 투어·장비·후기). 먼저 규강이 누구인지(About), 규강이 생각하는 것(Story)을 보여 준 뒤 프리다이빙 활동(Freediving)으로 이어지는 순서다. Phase 2에서 `Films`는 Freediving 뒤, Contact 앞에 추가된다.

## 4. 페이지별 콘셉트

**홈** — 메뉴 순서와 같은 흐름. 슬로건 히어로(수중 일러스트 유지)와 규강 소개 요약(About) → 최신 스토리 3건 → 진행 예정 투어 1~2건(모집 상태 뱃지)과 대표 후기 3건 → 인스타그램 링크. 진행 예정 투어가 없으면 "다음 투어 소식 받기"로 대체한다.

**About** — 규강 소개 페이지이자 사이트의 첫 메뉴. 바다에서의 경험과 창작을 한 사람의 이야기로 연결한다(기존 시안의 "서로 다른 두 세계. 하나의 호기심." 계승). 실제 이력·자격은 규강이 확인한 것만 기재한다.

**투어 목록/상세** — 목록은 위에 "진행 예정", 아래에 "지난 투어 아카이브". 상세는 대표 이미지/영상 → 핵심 정보(일정·장소·모집 상태·정원) → 상세 설명 → 이 투어의 후기 → 신청 폼 순서이고, 모바일에서는 하단에 "신청하기" 고정 버튼을 둔다. 지난 투어 상세는 신청 폼 대신 후기·갤러리·스케치 영상이 중심이다.

**장비** — 카드 그리드(썸네일·이름·한 줄 추천 이유), 카테고리 필터. 상세는 규강의 추천 이유를 먼저 보여주고 특징을 뒤에 둔다. 하단 버튼은 장비별 설정에 따라 "구매처 보기 ↗" 또는 "문의하기"이고, 없으면 숨긴다. 제휴 링크는 고지 문구를 같이 표시한다.

**스토리** — 일기/블로그 톤. 큰 대표 이미지, 읽기 좋은 본문 폭, 이미지 중심 에디토리얼 레이아웃. 글 하단에는 이전/다음 글과 인스타그램 링크 정도만 두고, **후기나 투어 광고는 넣지 않는다.** 읽는 경험을 지키기 위함이다.

## 5. 수강 후기 UX 배치 (2026-11-07 C안 확정)

### 5.1 비교

| 안 | 장점 | 단점 |
| --- | --- | --- |
| A. 독립 페이지만 | 구현 단순, 후기 모음 한눈에 | 방문자가 일부러 찾아가야 해서 **신뢰가 필요한 순간(신청 직전)에 노출되지 않음** |
| B. 각 페이지에 녹이기만 | 맥락 속에서 신뢰 형성 | 후기 전체를 볼 곳이 없고, 중복 입력·관리 부담, SEO 단일 랜딩이 없음 |
| **C. 하이브리드 (제안)** | 신뢰 순간에 노출 + 전체 보기 + 한 번 입력 | A+B의 구현을 모두 필요로 함(재사용 컴포넌트로 비용 절감) |

### 5.2 확정: C안 — "한 번 입력, 맥락별 노출, 전체는 한 곳에"

**데이터 흐름**
- 후기는 `Review` 한 곳에서만 입력한다. 투어 연결(선택)과 "대표 후기" 체크로 노출 위치가 결정된다.
- 동일한 `ReviewCard`/`ReviewList` 컴포넌트를 모든 곳에서 재사용한다.

**노출 위치**

| 위치 | 보여주는 후기 | 이유 |
| --- | --- | --- |
| 투어 상세 | 그 투어에 연결된 후기. 없으면 대표 후기 | 신청 직전의 가장 강한 신뢰 신호. 지난 투어는 후기가 핵심 콘텐츠 |
| 홈 | 대표 후기 3건 + "후기 전체 보기" | 첫 방문자의 신뢰 형성 |
| `/freediving/reviews` | 전체, 투어별 필터 | 모든 후기를 볼 수 있는 단일 랜딩 (SEO·공유 링크) |
| 스토리 | **노출 안 함** | 일기 톤 유지 (규강의 개인 공간) |
| 장비 | **노출 안 함** | 후기는 강습에 대한 것이라 맥락이 다름 |
| 푸터 | 후기 전체 링크만 | 사이트 전역 접근 경로 |

**근거**: (1) 후기의 가치는 "결정 직전"에 있다. (2) 1인 운영이라 입력 지점이 하나여야 한다. (3) 독립 페이지는 신뢰 콘텐츠를 검색·AI 인용 대상으로 만들어 준다. 기존 컨셉안(PRODUCT-CONCEPT)의 "후기는 수업 가까이에 둔다"는 방향과도 일치한다.

**열린 점**: 후기 작성자 표기 방식(실명/이니셜/닉네임)과 공개 동의. 평점은 쓸지 규강이 결정한다. 평점이 없는 편이 인용형 후기로서 더 신뢰를 준다는 점을 참고하라.

## 6. 어드민 콘셉트 — "콤팩트"

- 좌측 메뉴 6개: 대시보드 / 스토리 / 투어 / 장비 / 후기 / 미디어(+설정)
- **대시보드**: 오늘 해야 할 일만. 신규 투어 신청 N건, 임시저장 글 N건, 모집중 투어 N건
- **목록 → 편집** 2단계 구조로 통일. 모든 목록에 상태 필터와 검색
- **스토리 편집기**: 글 쓰는 데 집중하는 한 화면. 자동 임시저장, 이미지 붙여넣기/끌어놓기, 발행 버튼
- **투어 편집기**: 기본 정보 / 설명 / 미디어 / 후기 연결 탭. "신청" 탭에서 해당 투어의 접수 내역을 바로 확인
- **모바일 대응**: 신청 확인과 상태 변경이 폰에서 가능해야 한다
- 용어는 한국어로, 비개발자도 쓸 수 있는 문구로 표시한다

## 7. 톤과 카피 원칙

- 강습/투어 영역은 **차분하고 안심되는 톤**, 스토리는 **1인칭의 솔직한 톤**
- 투어는 "신청" 대신 **"예약 문의"**로 표기해 결제·확정과의 혼동을 막는다 (결제 기능이 없으므로)
- 실제 이력·자격·성과는 규강이 확인한 것만 기재한다. 없는 정보를 채우지 않는다
