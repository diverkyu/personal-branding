## 3. 테스트 환경 (먼저 정해야 할 것)

사람들이 쓰려면 사이트가 **인터넷 주소로 열려야** 한다. 지금은 개발 PC에서만 돈다.

| 방법 | 장점 | 단점 | 추천 |
| --- | --- | --- | --- |
| **A. Vercel 프리뷰 주소로 공유** | 링크 하나로 모바일·PC 어디서든 실제처럼 사용, 폼 저장까지 시험 | Vercel 프로젝트 만들기가 먼저 필요, 보호 설정 확인 필요 | **권장** |
| B. 개발 PC에서 직접 보여 주기 (화면 공유·대면) | 바로 가능, 설치 없음 | 참가자 기기(모바일)로 못 써 봄, 진행자가 PC를 잡고 있어야 함 | 규강과 1:1 대면 때만 |
| C. 스크린샷·화면 녹화 공유 | 가장 쉬움 | 직접 눌러 보는 테스트가 아님. **사용성 테스트로는 부족** | 보조 자료로만 |

### 3.1 방법 A 준비 절차 (소유자가 할 일 + 제가 도울 일)

1. **규강(저장소 소유자)이 직접**: GitHub 계정으로 Vercel에 가입해 `diverkyu/personal-branding`을 연결, 프로젝트 생성. **저장소 Owner만 연결할 수 있어서 작업자 계정으로는 할 수 없다**([INFRASTRUCTURE §9](INFRASTRUCTURE.md)). **Root Directory = `app`**, 프레임워크 Next.js 자동 인식. 가입·로그인·결제는 규강이 직접, 작업자는 화면 공유로 안내
2. **환경변수 (Preview 환경)**: `INQUIRY_STORE=postgres`, `DATABASE_URL`=Neon **`dev`** 브랜치 문자열, `SITE_URL`=프리뷰 주소(첫 배포 뒤 확인), `SITE_INDEXING`은 비움(= 색인 금지). 운영 문자열은 넣지 않는다. (비밀 값은 소유자가 Vercel 화면에 직접 입력)
3. **접근 보호**: Vercel은 프리뷰·운영 배포를 **Vercel Authentication**(Vercel에 로그인한 팀원만 열림)으로 보호할 수 있고, 모든 플랜에서 추가 비용 없이 쓸 수 있다고 공식 문서에 있다. 참가자는 Vercel 계정이 없으므로 두 가지 중 하나를 쓴다. (a) 보호된 배포에 **임시 공유 링크**(유효 기간 설정 가능, 공식 문서 확인)를 만들어 참가자에게 보낸다. (b) 프로젝트의 보호 설정을 끄고 주소만 아는 사람에게 연다. **(b)는 주소가 노출되면 누구나 열 수 있으니 테스트 기간에만 쓰고 끝나면 다시 켠다.** 암호 보호(Password Protection)는 Hobby에서 쓸 수 없고 Pro에서 프로젝트당 월 $20로 공식 문서에 적혀 있다. 기본값이 어떻게 설정되는지는 프로젝트를 만든 뒤 설정 화면에서 직접 확인한다.
4. **Hobby 조건 유지**: 이 테스트는 **내부 검수** 범위다. 실제 투어 모집, 제휴 링크 노출, 실제 신청 접수는 하지 않고, 참가자에게도 "테스트용"임을 알린다 ([INFRASTRUCTURE §2](INFRASTRUCTURE.md)).
5. 첫 배포에서 확인: 빌드 성공, 함수 지역 `sin1` 적용, 폼 제출이 `dev` DB에 저장, `noindex` 헤더, 글꼴·이미지 정상.

## 8. 테스트 전·후 점검 (진행자)

**전**
- [ ] 프리뷰 주소가 모바일·PC에서 열리고 `noindex`다 (검색에 노출되지 않음)
- [ ] 폼 제출이 `dev` DB에 저장된다 (운영 DB 아님을 문자열 대신 환경변수 위치로 확인)
- [ ] "(예시)" 콘텐츠와 가짜 정보 안내를 참가자에게 전달할 문구 준비
- [ ] 녹화 동의서/구두 동의 방법, 참가자 부호(P1~P6) 표
- [ ] 알려진 한계 공유: 어드민·메일·실제 콘텐츠 없음

**후**
- [ ] 접수된 시험 데이터를 `dev` DB에서 삭제 (개인정보가 섞였다면 즉시)
- [ ] 녹화 파일은 팀 안에서만 보관, 분석 뒤 삭제 기한 정하기
- [ ] 결과 요약을 문서(CHANGELOG 또는 별도)에 남기고 수정 PR로 연결

## 10. 알려진 한계 (이 테스트로 알 수 없는 것)

- **어드민 사용성**: 어드민이 없어 규강의 실제 운영 흐름은 시안 인터뷰로만 확인한다.
- **실제 콘텐츠의 힘**: 예시 글·사진으로는 글맛·사진 품질에 대한 반응을 알 수 없다.
- **실제 전환**: 사람들이 진짜로 문의하는지는 공개 뒤에 봐야 한다.
- **접근성 정밀 점검**: 스크린리더·보조기기 사용자 테스트는 이 계획에 포함하지 않았다(별도 필요). 자동 접근성 검사(axe)도 아직 하지 않았다.
- 표본이 작아 **통계적 결론은 낼 수 없고**, 반복해서 막히는 곳을 찾는 용도다.
