## 0. 이 문서는 무엇인가

화면 시안은 **"어떻게 보이는가"**만 보여 준다. 이 문서는 시안 위에 다음을 정한다.

- 화면의 각 요소가 **고정 디자인인지, 어드민에서 고칠 수 있는 내용인지, 자동으로 만들어지는지**
- 어떤 요소가 **버튼·링크·입력**이고 누르면 무엇이 일어나는지
- 어드민에서 **무엇을 어디서 수정할 수 있는지**, 그 필드의 제약
- 빈 상태, 오류, 로딩 등 **시안에 없는 상태**의 모습

> **시안이 없는 화면이 있다.** 공개 화면 6개(About, Story 상세, 장비 상세, 후기 전체, 개인정보 처리방침, 404·오류·완료)와 어드민 화면 7개(로그인, 투어, 장비, 후기, 미디어, About, 사이트 설정)는 시안이 없고, 투어 목록·장비 목록·Contact는 다른 화면의 일부로만 있다. 이 문서의 요소 표가 먼저 정의한다 (§3). 이 문서의 규칙 중 규강의 결정이 필요한 것은 **"제안"**으로 표시했고 §12에 모았다.

## 1. 읽는 법

### 1.1 요소 유형 코드

| 코드 | 이름 | 뜻 | 수정 방법 |
| --- | --- | --- | --- |
| **F** | 고정 디자인 | 브랜드 뼈대. 색, 글꼴, 레이아웃, 일러스트, 섹션 구성 | 개발 요청 (어드민에서 못 고침) |
| **C** | 콘텐츠 | 글, 투어, 장비, 후기처럼 항목마다 다른 내용 | 어드민의 해당 콘텐츠 편집 화면 |
| **S** | 사이트 설정 | 여러 곳에 쓰이는 공통 문구·링크 | 어드민 > 사이트 설정 |
| **A** | 자동 | 데이터에서 자동으로 만들어짐 (날짜, 개수, 최신 글 목록, 연도) | 직접 수정 불가. 원인 데이터를 고침 |
| **B** | 버튼·링크 | 누르면 동작하는 요소 | 라벨은 F 또는 S, 목적지는 표에 명시 |
| **I** | 입력 | 방문자가 값을 넣는 폼 요소 | 항목 구성은 F, 안내 문구는 S |

한 요소가 두 코드를 가질 수 있다 (예: 라벨은 S, 동작은 B).

### 1.2 요소 ID

`화면코드-번호` (예: `HOME-03`). 개발·검증·수정 요청에서 이 ID로 요소를 가리킨다 ([DEVELOPMENT §11](DEVELOPMENT.md)). 시안 파일 이름은 §3에 매핑했다.

### 1.3 근거

PRD 요구사항 ID(S-, T-, E-, R-, A-, W-)를 함께 적는다. 이 문서가 PRD에 없는 요구를 발견하면 §13에 모아 PRD 개정을 제안한다.

## 2. 무엇을 고칠 수 있게 할까 — 편집 원칙

규강이 코드 없이 바꿀 수 있어야 하는 것과, 바뀌면 브랜드가 흔들리는 것을 나눈다.

| 층 | 포함 | 바꾸는 방법 | 이유 |
| --- | --- | --- | --- |
| **고정(F)** | 로고, 색상, 글꼴, 아이콘, 레이아웃과 섹션 순서, 메뉴 구조(항목과 순서), 수중 일러스트, 섹션 번호 라벨, 폼 항목 구성 | 개발 요청 | 일관된 브랜드와 안전성. 어드민이 복잡해지는 것을 막는다 |
| **사이트 설정(S)** | 히어로 헤드라인·소개문, 구분 띠 문구, 섹션 제목·부제, About 서명, 연락 이메일, SNS 링크, 푸터 문구, 폼 안내·동의·완료 문구, SEO 기본값 | 어드민 > 사이트 설정 | 자주는 아니지만 코드 없이 고쳐야 하는 문구 |
| **콘텐츠(C)** | 스토리, 투어, 장비, 후기, About 본문 | 어드민 > 각 콘텐츠 | 계속 늘어나는 내용 |
| **자동(A)** | 최신 글 목록, 모집 상태 뱃지(규칙에 따른 것), 연도, 이전·다음 글, 개수 | 원인 데이터를 고침 | 수동 관리 실수를 없앤다 |

**어드민 원칙**
- 규강이 하루에 하는 일(글 쓰기, 투어 등록, 신청 확인)은 **세 번 클릭 안에** 도달한다.
- 레이아웃을 바꾸는 기능(드래그로 섹션 배치, 색 선택)은 **만들지 않는다.** 디자인 시스템이 무너지는 가장 빠른 길이다.
- 고정 영문 슬로건 `Dive deeper. Create beyond.`는 브랜드의 핵심이므로 **확인 단계를 둔 사이트 설정(S)** 으로 확정했다 (§12 결정 1, 2026-11-08).

### 4.4 공통 규칙

- 한 화면에 `h1`은 하나. 제목 단계는 건너뛰지 않는다 (디자인 시스템 H1~H4와 별개로 의미 단계를 지킨다).
- 포커스 외곽선은 `--kyu-focus` 3px ([DESIGN-SYSTEM §5](DESIGN-SYSTEM.md)). 모든 버튼·링크는 키보드로 접근된다.
- 아이콘만 있는 버튼에는 `aria-label`. 장식 아이콘은 `aria-hidden="true"`.
- 성공·오류 안내는 `role="status"` (오류는 필요 시 `role="alert"`).
- 날짜 표기 `2026.11.08`. 기간은 `2026.11.08 – 11.10`.

## 7. 어드민 설계

### 7.1 구조

좌측 메뉴 (폭 240, 모바일에서는 상단 햄버거): 대시보드 / 스토리 / 투어·신청 / 장비 / 수강 후기 / 미디어 / About / 사이트 설정. 우측 상단: 사이트 보기(새 탭), 로그아웃.

원칙: **목록 → 편집 2단계**로 통일한다. 모든 목록은 검색, 상태 필터, 정렬을 가진다.

### 7.2 공통 규칙

| 항목 | 규칙 |
| --- | --- |
| 목록 | 검색(제목), 상태 필터, 정렬(수정일 기본), 페이지당 20건 |
