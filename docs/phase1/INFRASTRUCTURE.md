## 2. 호스팅: Vercel (Hobby로 시작, 조건부)

**2026-11-08 결정**: "당장은 상업용 용도가 아니니 Vercel Hobby로 시작한다."

**알아야 할 제한 (공식 [fair use guidelines](https://vercel.com/docs/limits/fair-use-guidelines)에서 확인)**
- Hobby는 **비상업적 개인 용도 전용**이고, 상업적 사용에는 Pro 또는 Enterprise가 필요하다.
- 커뮤니티 운영자 답변은 "프로젝트에 관여한 누구라도 금전적 이득을 얻을 목적으로 쓰는 배포"를 상업적 사용으로 본다고 인용한다. 이 사이트는 **투어 모집, 장비 구매 링크(제휴 수수료), 향후 상품 판매**가 목적이라 공개 운영 단계에서는 상업적 사용에 해당할 가능성이 높다. 경계가 애매한 경우의 판단은 Vercel만이 할 수 있다.
- Pro의 월 가격은 제3자 글에서 약 $20로만 확인했다 (공식 가격 페이지 재확인 필요).

**이 결정이 유효한 범위 (조건)**
1. Hobby는 **개발·프리뷰·내부 검수 단계에서만** 쓴다. 이 기간에는 실제 투어 모집, 제휴 링크 노출, 실제 방문자 신청 접수를 하지 않는다.
2. **공개 게시(PRD §12.2 R5) 이전, 또는 투어 모집을 처음 시작하기 이전 중 빠른 때에 Pro로 전환한다.** 이 항목을 R5 체크리스트(PRD §12.3)에 넣는다.
3. 전환 시점의 판단이 애매하면 Vercel에 직접 문의한다.
4. 계정(팀) 소유자·요금제 결제 주체는 공동 작업자와 규강이 정한다 (PRD §12.5, 대기).

**호스팅에 묶이지 않기 위한 원칙 유지**: 호스팅 전용 기능에 직접 기대는 코드를 넣지 않는다. 데이터 접근은 `data/` 어댑터 뒤에 둔다 (AGENTS §3, DEVELOPMENT §10 교체 가능한 경계).

## 3. 데이터베이스: Neon Postgres (잠정)

**질문(2026-11-08)**: "Neon Postgres가 유료로 사용하는 거야?" → **무료 플랜이 있고, 한도를 넘기면 사용량 기반 유료 플랜을 쓴다.**

| 플랜 | 내용 (Neon 공식 [plans 문서](https://neon.com/docs/introduction/plans)·[pricing](https://neon.com/pricing) 검색 결과 기준) |
| --- | --- |
| Free | 월 $0, 신용카드 불필요. 프로젝트당 Postgres 저장 1GB(전체 최대 20GB), 프로젝트당 100 CU-시간, 외부 전송 5GB. 호출이 없으면 5분 뒤 자동으로 잠들고 요청 때 몇백 ms 안에 깨어난다 |
| Launch | 최소 요금 없는 사용량 기반. 저장 $0.35/GB-월, 연산 $0.106/CU-시간 |
| Scale | 같은 방식, 연산 $0.222/CU-시간, 프로젝트·브랜치 한도 더 큼 |

- 이 사이트의 데이터(신청·문의, 글, 투어, 장비, 후기)는 작아서 **무료 플랜 한도 안에 들어갈 가능성이 크다**. 이 판단은 구현 후 실제 사용량으로 다시 확인한다.
- **확인 대기**: 무료 플랜을 **상업 서비스에 써도 되는지**는 이번 조사에서 확인하지 못했다. 공개 운영 전에 Neon 약관으로 확인하고, 안 되면 Launch(사용량 기반)로 올린다. 비용은 월 몇 달러 수준에서 시작하지만 실제 청구는 사용량에 따른다.
- 대체안: Supabase(DB·인증·파일을 묶음, 무료 플랜은 1주일 비활동 시 프로젝트 일시정지, 제3자 글 기준), SQLite 계열(Turso 등).
- 환경 분리: **프리뷰·개발 DB는 운영 DB와 분리**한다 (PRD §12.1). Neon의 브랜치 기능을 쓸 수 있다.

**구현 현황 (0.18.0)**
- 구현: `inquiries` 표 스키마·마이그레이션, Postgres 저장 어댑터(`INQUIRY_STORE=postgres` + `DATABASE_URL`), Neon HTTP 드라이버. PGlite(실제 Postgres 엔진)로 마이그레이션·저장·제약을 시험했다.
- **확인함(2026-11-08, 0.18.1): 실제 Neon 서버 연결·마이그레이션·폼 저장·되읽기.** 프로젝트 `diverkyu`(AWS 싱가포르, Postgres만 사용)의 운영 브랜치에서 확인했다. 아래 절차는 개발·프리뷰 DB를 새로 만들 때 그대로 쓴다.
- 소유자가 할 일(비밀번호·연결 문자열은 코드·대화·저장소에 넣지 않는다):
  1. Neon 계정에서 프로젝트를 만든다. **운영용과 개발·프리뷰용을 따로** 만들거나 브랜치로 나눈다.
  2. 연결 문자열을 `app/.env.local`의 `DATABASE_URL`에 넣고 `INQUIRY_STORE=postgres`로 둔다 (Vercel에는 환경별 환경변수로).
  3. `cd app && npm run db:migrate`로 표를 만든다.
  4. 개발 서버에서 폼을 제출해 Neon 콘솔의 `inquiries` 표에 행이 생기는지 확인한다.
- 신청 데이터는 개인정보(이름·연락처·이메일)다. 보관 기간·파기 방식은 SECURITY §16 대기 항목이며, 어드민 접근 통제가 생기기 전에는 DB 콘솔 접근 권한을 소유자·공동 작업자로 제한한다.

**환경 분리 (0.18.2)**

| 환경 | Neon 브랜치 | 설정 위치 |
| --- | --- | --- |
| 로컬 개발 | `dev` | `app/.env.local` (git 제외) |
| Vercel Preview·Development | `dev` | Vercel 환경변수 (Preview·Development) |
| Vercel Production | `production` | Vercel 환경변수 (**Production에만**) |

- 운영 연결 문자열은 Production 환경에만 넣는다. 로컬과 프리뷰에는 `dev` 문자열만 둔다.
- `dev`는 `production`의 자식 브랜치다. 운영에 실제 신청 데이터가 쌓인 뒤에 `dev`를 다시 만들거나 갱신할 때는 **개인정보가 복사되지 않도록 "스키마만" 또는 익명화 옵션**을 쓴다 (지금은 데이터가 없다).
- 스키마를 바꾸는 마이그레이션은 `dev`에서 먼저 적용해 확인하고, 운영에는 배포 전에 적용한다.

**함수 지역 (0.18.2)**: `app/vercel.json`의 `regions: ["sin1"]`(싱가포르). Neon과 같은 AWS 지역이라 함수↔DB 왕복이 짧다. 사용자(한국)는 정적 파일을 가까운 CDN에서 받고, 함수는 폼·어드민에서만 쓴다. 지역 변경은 이 파일 한 줄이다(서울 `icn1` 등).

## 4. 접수 알림 메일: Resend

- 제3자 글 기준 무료 플랜은 월 3,000통·일 100통, 검증된 발신 도메인 1개 (공식 가격 재확인 필요). 투어 문의 규모에는 충분할 것으로 본다.
- 발신 도메인 인증(SPF·DKIM)이 필요하므로 **도메인이 정해진 뒤**에 연결한다. 그 전에는 시험 발송만 한다.
- SECURITY §8 유지: 알림 실패해도 신청은 저장하고 어드민에 실패를 표시한다. 수신자·제목에 사용자 입력을 넣지 않는다. 프리뷰에서는 실제 발송을 끈다.
- 메일은 `data/` 어댑터 뒤에 두어 서비스를 바꿀 수 있게 한다.

## 5. 어드민 인증: 인증 라이브러리 + TOTP

- 검증된 라이브러리(Better Auth 또는 Auth.js)를 DB에 연결하고 TOTP(인증 앱) 2차 인증을 켠다. 직접 구현하지 않는다 (SECURITY §2·§16).
- 구현 단계에서 두 라이브러리의 **현재 문서와 Next.js 16 호환**을 확인한 뒤 하나를 고른다.
- 비밀번호 재설정(이메일 링크 vs 운영자 수동)과 편집자 역할 도입 시점은 SECURITY §16 대기 항목으로 남는다.

### 9.1 확인한 사실 (공식 문서, 2026-11-08 조회)

| 서비스 | 사실 |
| --- | --- |
| GitHub + Vercel | 저장소 `diverkyu/personal-branding`은 **규강의 개인 계정 소유**이고 작업자는 Collaborator다. Vercel 문서: 개인 계정 저장소는 **저장소 Owner만** Vercel 프로젝트로 가져오거나 연결할 수 있고, **Collaborator는 새 프로젝트를 만들거나 기존 프로젝트에 연결할 수 없다**([Vercel for GitHub](https://vercel.com/docs/git/vercel-for-github)). 따라서 Git 연결은 **규강의 GitHub 로그인으로** 해야 한다 |
| Vercel Hobby | 비공개 저장소는 커밋 작성자가 Hobby 팀 소유자여야 배포된다(그 문서의 제한은 "비공개 저장소" 기준)([Git](https://vercel.com/docs/git)). 지금 저장소는 **공개**라 이 제한이 적용되는지는 **첫 배포에서 확인**해야 한다(미확인). 비공개로 바꾸면 작업자의 커밋은 Hobby에서 배포되지 않는다 |
| Vercel 프로젝트 이전 | 원래 팀의 Owner이고 받는 팀의 멤버여야 한다. 코드(24시간 유효)로 받는 방식도 있다([Transferring a project](https://vercel.com/docs/projects/transferring-projects)). 이전하면 **Git 연결은 다시 해야** 한다 |
| Vercel Pro 요금 | 플랫폼 월 $20(배포 가능 자리 1개 + $20 사용 크레딧 포함), 배포·설정 권한이 있는 추가 멤버는 1명당 월 $20, **Viewer(읽기 전용)는 무료**([Pro plan](https://vercel.com/docs/plans/pro-plan)) |
| Neon 프로젝트 이전 | 콘솔 Settings에서 조직 간 이전, 또는 **받는 사람이 수락하는 링크(기본 24시간 유효)**. **연결 문자열은 유지**돼 앱 설정을 바꿀 필요가 없고, 청구·사용량은 받는 조직으로 넘어간다. 받는 쪽 플랜이 같거나 높아야 하고, 이전 전에 GitHub·Vercel 연동은 해제해야 한다([Transfer projects](https://neon.com/docs/manage/orgs-project-transfer)) |

| --- | --- | --- | --- |
| **A. 처음부터 규강 소유** (작업자는 초대받은 멤버) | 규강 계정으로 프로젝트 | 규강이 GitHub로 로그인해 프로젝트 생성·저장소 연결, 작업자는 나중에 멤버/Viewer로 초대 | 인수인계가 필요 없고 권한이 처음부터 맞다. **규강이 한 번 같이 앉아야 한다**(화면 공유 가능, 약 15~30분) |
| **B. 작업자가 만들고 나중에 이전** | 쉬움: 수락 링크로 이전, 연결 문자열 유지 | **불리함**: 작업자는 규강 저장소를 Vercel에 연결할 수 없어 Git 연동 없이 CLI로 배포해야 하고, 이전 뒤 규강이 Git을 다시 연결해야 한다. 이전 자체도 작업자가 규강 팀의 멤버여야 한다 | 일이 두 번이다 |
| **C. 혼합 (권장)** | **지금은 작업자 계정 유지, 공개 운영 전에 규강에게 수락 링크로 이전**(연결 문자열이 그대로라 코드·환경변수 변경 없음) | **처음부터 규강 계정으로** (Git 연결 때문에) | 규강이 해야 할 일이 가장 적고 안전하다 |

### 9.3 권장 절차 (C)

1. **규강**(화면 공유로 작업자와 함께): GitHub 계정으로 Vercel에 가입 → `personal-branding` 저장소 가져오기 → Root Directory `app`. 가입·로그인·카드 입력은 규강이 직접 한다.
2. **규강**: Preview 환경변수에 Neon `dev` 연결 문자열 입력 (`INQUIRY_STORE=postgres`, `DATABASE_URL`). 비밀 값이라 작업자가 대신 입력하지 않는다. 작업자는 연결 문자열을 안전한 방법(대면·비밀번호 관리자 공유 기능)으로 전달하고, **메신저·이슈·문서에 붙이지 않는다**.
3. 첫 프리뷰 배포에서 확인: 빌드, 함수 지역 `sin1`, 폼 저장, `noindex`, 작업자 커밋이 Hobby에서 배포되는지.
4. 사용자 테스트([USER-TEST.md](USER-TEST.md)) 진행.
5. **공개 운영 전(또는 투어 모집 시작 전)**: 규강이 Vercel을 **Pro로 전환**하고(§2), 필요하면 작업자를 멤버로 초대한다. 작업자가 설정을 바꿀 일이 없으면 **Viewer(무료)** 로 충분하다. 멤버(배포·설정 권한)는 1명당 월 $20.
6. **Neon 이전**: 규강이 Neon 계정을 만들고 작업자가 수락 링크로 프로젝트를 보낸다 → 연결 문자열 유지 확인 → 이후 청구는 규강. 운영 전 Neon 무료 플랜 상업 사용 약관을 확인한다(§3).

### 9.4 소유·보안 원칙

- **모든 서비스의 소유자(Owner)는 규강**, 복구 이메일과 2단계 인증도 규강 소유 수단으로 둔다. 작업자는 필요한 최소 권한의 멤버로 초대한다. **비밀번호·세션을 공유하지 않는다.**
- 결제 수단은 규강의 것. 작업자 개인 카드로 시작했다면 이전 전에 규강 카드로 바꾼다.
- 작업자 계정이 일시적으로 소유자인 서비스(예: 지금의 Neon)는 인수인계 시점을 정해 두고, 이전 후 작업자 쪽에서 연동·키를 정리한다.
- 인수인계 체크리스트: ① 소유자 변경 확인 ② 연결 문자열·환경변수 동작 확인(`npm run db:migrate` 또는 폼 저장 확인) ③ 이전 소유자의 API 키·토큰 폐기 ④ 결제 수단과 알림 이메일 ⑤ 2단계 인증 ⑥ 복구 방법 문서화.

### 9.5 아직 확인하지 못한 것

- 공개 저장소에서 협업자 커밋이 **Hobby**에서 배포되는지, 그리고 **Pro 팀**에서 협업자가 팀 멤버가 아닐 때 배포되는지 (첫 배포에서 확인)
- Hobby에서 Pro로 **올릴 때 기존 프로젝트·환경변수가 그대로 유지되는지** (공식 문서로 확인하지 않음)
- Neon 이전 시 `dev`·`production` 브랜치와 마이그레이션 기록이 그대로 유지되는지 (이전 후 확인)

## 10. 첫 프리뷰 배포 절차 (규강 + 작업자, 화면 공유)

**준비물**: 규강의 GitHub 로그인, Vercel 가입에 쓸 규강 이메일, Neon `dev` 연결 문자열(작업자가 대면·화면 공유 중 직접 복사해서 규강이 입력 칸에 붙여넣거나, 규강이 Neon 화면의 Connect에서 직접 복사). **연결 문자열을 메신저·문서에 붙이지 않는다.**

### 10.1 단계

1. 규강이 [vercel.com](https://vercel.com)에서 **Continue with GitHub**로 가입한다(무료 Hobby). 플랜 선택은 Hobby.
2. **Add New → Project**에서 저장소 `diverkyu/personal-branding`을 **Import**한다. (GitHub 권한 창에서 Vercel 앱에 이 저장소 접근을 허용)
3. 설정 화면에서 아래처럼 맞춘다.

| 항목 | 값 |
| --- | --- |
| Framework Preset | Next.js (자동 인식) |
| **Root Directory** | **`app`** (Edit을 눌러 선택) |
| Build·Install·Output | 기본값 그대로 (`npm run build` 등) |
| Node.js 버전 | 24.x (프로젝트 Settings → General에서 확인, 저장소는 24 이상 필요 — [app/README](../../app/README.md)) |

4. **Environment Variables** (첫 배포 전에 입력):

| 이름 | 값 | 적용 환경 | 비고 |
| --- | --- | --- | --- |
| `INQUIRY_STORE` | `postgres` | Production, Preview | |
| `DATABASE_URL` | Neon **`dev`** 연결 문자열 | Production, Preview | 비밀 값. **Sensitive 표시 옵션이 보이면 켠다.** 지금은 Production에도 `dev` 문자열을 둔다 — 아직 실제 방문자가 없는 시험 단계이기 때문이다. **공개 운영 전에 Production만 `production` 문자열로 바꾼다**(§3, 체크리스트 §10.4) |
| `SITE_URL` | 첫 배포 뒤 확정되는 프로젝트 주소(`https://….vercel.app`) | Production, Preview | 첫 배포 때는 비워 두고, 주소가 정해진 뒤 입력하고 **다시 배포**한다(주소는 빌드 때 반영된다 — app/README) |
| `SITE_INDEXING` | **설정하지 않는다** | — | 비어 있으면 검색 색인 금지(noindex)다 |
| `ENABLE_COMPONENT_SHOWCASE` | **설정하지 않는다** | — | 개발용 쇼케이스가 열리지 않게 |

5. **Deploy**를 누른다. 빌드가 끝나면 주소가 나온다. `app/vercel.json`의 `sin1`이 함수 지역으로 쓰인다.
6. **접근 보호**: Project Settings → Deployment Protection에서 현재 설정을 확인한다. 테스트 참가자가 열려면 임시 공유 링크를 만들거나 테스트 기간만 보호를 끈다([USER-TEST §3.1](USER-TEST.md)). 끈 경우 끝나면 다시 켠다.
7. 작업자 초대는 지금은 하지 않는다(Hobby는 멤버를 둘 수 없다). Pro 전환 때 Viewer 또는 Member로 초대한다(§9.3).

### 10.2 배포 확인 (작업자가 실행)

주소(접근 보호 중이면 공유 링크 전체)를 알려 주면 작업자가 아래 시험을 돌린다.

```bash
cd app
REMOTE_URL="https://주소" REMOTE_EXPECT_REGION=sin1 npm run test:remote
npm run db:cleanup-smoke   # 시험이 남긴 가짜 문의(smoke-*@example.com)를 dev DB에서 삭제
```

확인 내용: 홈과 주요 화면 열림, noindex·보안 헤더, robots.txt 전체 차단, 개발용 쇼케이스 404, **예약 문의 제출이 접수되고(= Vercel → Neon 연결 동작)**, 폼을 처리한 **함수 지역이 `sin1`인지**(응답 헤더 `x-vercel-id`). 이 시험은 모바일 폭(390px)에서 실행한다.

### 10.3 자주 막히는 곳

| 증상 | 원인·조치 |
| --- | --- |
| 저장소가 목록에 안 보임 | Vercel 앱의 GitHub 접근 권한 설정에서 저장소를 허용 |
| 빌드 실패: 폴더를 못 찾음 | Root Directory가 `app`인지 확인 |
| 접수 때 "전송하지 못했습니다" | `INQUIRY_STORE`·`DATABASE_URL` 누락 또는 오타, 환경 선택(Production/Preview) 확인. 환경변수를 바꾼 뒤에는 **다시 배포**해야 반영된다 |
| 열리지 않고 로그인 화면이 뜸 | 접근 보호(Vercel Authentication). 공유 링크 사용 |
