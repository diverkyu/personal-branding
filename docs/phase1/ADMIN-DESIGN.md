# 어드민 기술 설계

> 문서 버전 **0.35.0** (PRD·CONCEPT·SCREEN-SPEC 등과 같은 세트 버전, [CHANGELOG](CHANGELOG.md)) · 상태: 검토 중

[SCREEN-SPEC §7](SCREEN-SPEC.md)이 어드민 **화면·필드**를 정했다면, 이 문서는 그것을 **어떻게 만들지**를 정한다. 인증, 권한, 데이터 모델, 편집기, 이미지, 저장·충돌 처리, 구현 순서를 다룬다. 화면 필드와 제약은 SCREEN-SPEC을 따르고 여기서 반복하지 않는다.

## 2. 원칙

1. **서버가 모든 것을 다시 검사한다.** 미들웨어(프록시)의 로그인 확인은 편의일 뿐이다. 모든 어드민 페이지·서버 액션·데이터 조회 함수가 스스로 세션과 권한을 확인한다 (SECURITY §3).
2. **공개 조회와 어드민 조회는 다른 함수다.** 공개 함수는 `published` 등 공개 상태만 반환하며, 필터를 화면이 아닌 **데이터 함수 안에서** 건다.
3. **레이아웃을 바꾸는 기능은 만들지 않는다** (SCREEN-SPEC §2).
4. **실패해도 데이터는 안 잃는다.** 저장 실패는 화면에 표시하고 입력을 보존한다. 외부 서비스(Blob, 메일) 실패가 콘텐츠 저장을 막지 않는다.
5. **쉬운 한국어.** 개발 용어(slug, draft)는 화면에서 "주소 이름", "임시저장"으로 푼다.

- 시안: 2026-11-08 대화에서 확정한 메뉴 구조 (세션 시안, 필요 시 `mockup/`에 정식 시안으로 추가).

### 3.2 코드 구조

```
app/src/app/admin/
  login/                 # 비로그인 허용 (유일한 예외)
  login/two-factor/      # 비밀번호 통과 후 TOTP 입력
  setup-2fa/             # 첫 로그인 시 TOTP 등록 (2차 인증 미등록 계정은 여기서 막힘)
  (console)/             # 로그인 필수 영역. layout에서 세션 확인
    page.tsx             # 대시보드
    contents/ schedule/ automation/ trash/
    tours/ inquiries/ reviews/ equipment/
    media/ taxonomy/ pages/ settings/ legal/
    users/ audit/ integrations/ backup/
app/src/app/api/auth/[...all]/route.ts   # Better Auth 핸들러
app/src/app/api/ingest/route.ts          # 자동화 입력 (토큰 인증, 항상 초안으로만 저장, 후속)
app/src/lib/auth/        # auth 인스턴스, requireAdmin(), 세션 헬퍼
app/src/content/types/   # 콘텐츠 유형 정의 (story, video, travel ...)
app/src/content/publish/ # 발행 상태 전이, 예약, 발행 작업
app/src/admin/           # 어드민 전용 컴포넌트·서버 액션·검증 스키마
app/src/data/admin/      # 어드민 조회·변경 함수 (모두 requireAdmin 선행)
app/src/data/public/     # 공개 조회 함수 (공개 상태만)
```

- 어드민 경로 응답은 `Cache-Control: no-store`, `noindex` (SECURITY §12). 어드민 스타일은 공개 사이트와 분리한 CSS 모듈로 둔다.
- `data/admin/*`의 모든 함수는 첫 줄에서 `requireAdmin()`을 호출한다. 호출이 빠지면 시험에서 잡히도록 함수 목록 대비 시험을 둔다 (§12).

## 4. 인증과 세션

### 4.1 구성

- `betterAuth({ database: drizzleAdapter(db, { provider: "pg" }), emailAndPassword: { enabled: true, disableSignUp: true }, plugins: [twoFactor()] })`
- **가입 차단**: 공개 가입은 없다. `disableSignUp: true`로 막고, 계정은 서버에서 한 번 실행하는 스크립트로만 만든다 (§4.2).
- **세션**: 최대 8시간 (`expiresIn: 28800`), 쿠키 `HttpOnly`·`Secure`·`SameSite=Lax`. 로그아웃·비밀번호 변경 시 세션을 서버에서 폐기한다. 쿠키 캐시는 쓰지 않는다 (폐기가 즉시 반영돼야 함).
- **속도 제한**: 로그인·2차 인증 경로에 엄격한 한도(예: 5회/10분)를 둔다. 저장소는 DB 기반이어야 서버리스 인스턴스 간에 공유된다 (메모리 저장은 인스턴스마다 따로 센다 — 공개 폼의 `rateLimit.ts`와 같은 한계, 어드민에서는 DB 저장으로 보완).
- **로그**: 로그인 성공·실패·잠금, 2차 인증 실패, 권한 거부, 세션 폐기를 구조화 로그로 남긴다. 이메일은 로그에 마스킹한다 (기존 logger 규칙).

### 4.2 첫 관리자 계정 만들기 (가입 없이)

1. 작업자가 `npm run admin:create` 스크립트를 로컬에서 실행한다. 이메일과 임시 비밀번호는 **터미널 입력(`read -s`)** 으로 받고 화면·로그에 출력하지 않는다.
2. 스크립트는 `DATABASE_URL`이 가리키는 DB(dev 또는 production 브랜치)에 사용자를 만든다. production 계정은 **규강이 직접** 실행하거나, 작업자가 화상 통화에서 규강 본인의 비밀번호 입력을 받지 않는 방식(임시 비밀번호 → 첫 로그인 때 변경 강제)으로 한다.
3. 첫 로그인 시 **비밀번호 변경 + TOTP 등록이 끝나기 전에는 어드민 어느 화면도 열리지 않는다** (`setup-2fa`로 강제 이동).
4. TOTP 등록 시 **복구 코드**를 발급한다. 규강이 안전한 곳에 보관하게 안내한다 (화면 문구 필요).

> 계정 생성·비밀번호·TOTP 비밀은 작업자가 대신 입력하거나 보관하지 않는다 (프로젝트 보안 규칙).

### 4.3 비밀번호 재설정·잠금 복구 (Phase 1)

- Resend 메일은 아직 없다. Phase 1은 **운영자 수동 재설정**(`npm run admin:reset-password`, 가입 스크립트와 같은 방식)으로 한다. 메일 도입 후 링크 방식으로 바꿀지는 SECURITY §16 열린 결정.
- TOTP 기기 분실: 복구 코드로 로그인 → 새 기기 등록. 복구 코드도 잃으면 운영자가 스크립트로 2차 인증을 초기화한다 (본인 확인은 규강-작업자 간 별도 채널, 로그 남김).

### 4.4 경로 보호의 3겹

1. `proxy`(미들웨어): `/admin/*`(login 제외)에 세션 쿠키가 없으면 로그인으로 이동 — 빠른 차단용.
2. `(console)/layout.tsx`: 서버에서 세션 + 2차 인증 완료 여부 확인.
3. `data/admin/*`와 서버 액션: 호출마다 `requireAdmin()`. **IDOR 방지**: ID로 조회할 때도 관리자 권한을 확인하고, 존재하지 않으면 404.

## 5. 데이터 모델

기존 `inquiries` 테이블은 유지한다. Better Auth가 `user`·`session`·`account`·`verification`·`twoFactor` 테이블을 만든다 (Drizzle 스키마를 `db/schema.ts`에 병합, 마이그레이션은 `drizzle-kit`).

### 5.1 공통 컬럼 (콘텐츠 테이블)

| 컬럼 | 용도 |
| --- | --- |
| `id` | uuid (내부 식별자) |
| `slug` | 고유 주소 이름 (스토리·투어·장비). 예약어 거부 |
| `status` | 공개 상태 (테이블별 허용 값 check 제약) |
| `version` | 정수. 저장마다 +1. **낙관적 잠금**에 사용 (§7) |
| `created_at` / `updated_at` | 시각 |
| `deleted_at` | 휴지통. NULL이 아니면 삭제됨. 30일 뒤 영구 삭제 (§8) |
| `updated_by` | 마지막 수정한 관리자 id (감사) |

### 5.0 통합 콘텐츠 모델 (`contents`)

발행형 콘텐츠(스토리, AI 영상, 여행 추천, 이후 유형)는 **한 테이블**에 둔다.

| 컬럼 | 설명 |
| --- | --- |
| `type` | 유형 키 (`story`, `video`, `travel` …). 코드의 유형 정의에 등록된 값만 허용 |
| 공통 | title, slug(유형 안에서 고유), summary, cover_media_id, cover_alt, body(JSON), tags(text[]), answers(text[]), seo_title, seo_description |
| `fields` | JSON. **유형별 항목** (여행 추천: region, season, level, budget, place, checked_on / 영상: video_url, duration, has_captions). 유형 정의의 스키마로 서버가 검증 |
| `status` | `draft` / `review` / `scheduled` / `published` / `archived` (§14.2) |
| `publish_at` | 예약 시각 (`scheduled`일 때 필수) |
| `published_at` | 실제 공개 시각 (서버 기록) |
| `origin` | `manual` / `ai_assisted` / `automated` (제작 방식, 공개 표기·검토 기준에 사용) |
| `origin_note` | 비공개 메모 (사용 도구·프롬프트 등) |

- 유형별 항목을 JSON으로 두는 이유: 유형이 늘어도 테이블·마이그레이션을 늘리지 않는다. 대신 **유형 정의(`content/types/*`)가 스키마의 단일 출처**이고, 읽기·쓰기 모두 이 정의로 검증한다. 검색·정렬에 쓰는 항목(예: 지역)이 생기면 그때 컬럼으로 승격한다.
- **별도 테이블로 두는 것**: `tours`(신청 폼·모집 상태와 결합), `equipment`, `reviews`(동의 확인·수정 이력), `about`, `site_settings`. 단 이들도 `status` 의미와 예약·휴지통·이력은 같은 발행 모듈을 쓴다 (§14).
- 공개 조회 함수는 `type`별로 `status='published' AND deleted_at IS NULL AND publish_at<=now()`만 반환한다.

| `publish_jobs` | id, target_type, target_id, run_at, state(`pending`/`running`/`done`/`failed`), attempts, last_error_kind, channel(`site`) | 예약 발행·자동 생성 작업 기록 (§14.3). 오류 메시지 원문은 저장하지 않음 |
| `ingest_tokens` | id, label, hash, allowed_types(text[]), created_by, created_at, revoked_at | 자동화 입력용. 토큰 원문은 발급 때 한 번만 표시, DB에는 해시만 (후속) |
| `audit_log` | at, actor_id, action, target_type, target_id, meta(JSON, 개인정보 제외) | 열람·내보내기·삭제·발행 등 (SECURITY §14) |
| `inquiries` (기존) | + `status`, `memo`, `handled_at` 컬럼 추가 | 원본 필드는 읽기 전용 |

- 본문(`body`)은 Tiptap JSON. **저장 시 서버가 허용 목록으로 다시 걸러서** 저장한다 (§6).
- 목록 조회는 페이지 크기 상한(20, 최대 100)을 둔다.

### 5.3 공개 화면 전환

지금 공개 화면은 `data/` 안의 고정 데이터(fixtures)를 읽는다. 어드민 단계에서 **같은 함수 시그니처를 유지한 채** 구현을 DB로 바꾼다 (`data/public/*`). 공개 함수는 `status`가 공개이고 `deleted_at IS NULL`인 행만 돌려준다. 미리보기는 별도의 어드민 경로에서 관리자 세션이 있을 때만 상태를 무시하고 보여준다 (INT-12, 비공개 URL 직접 접근은 404).

## 6. 리치 텍스트 (Tiptap)

- **허용 서식**: 문단, 제목(h2·h3), 굵게, 기울임, 링크(`https`만), 순서/비순서 목록, 인용, 구분선, 이미지(미디어 라이브러리 항목만), 영상 임베드(허용 도메인만). 그 외 노드·마크는 스키마에서 제외한다.
- **저장**: JSON. 서버 액션에서 같은 스키마로 검증하고, 허용되지 않은 노드·속성은 거부(또는 제거)한다. 클라이언트 편집기의 제한은 보안 경계가 아니다.
- **렌더링**: 공개 화면은 JSON을 **React 요소로 직접 렌더링**한다 (HTML 문자열을 `dangerouslySetInnerHTML`로 넣지 않는다). 링크에는 `rel="noopener noreferrer"`, 외부 링크 표시. 이미지는 `next/image`, 영상은 기존 `VideoPlayer` 허용 목록 경로.
- **한국어 입력(IME)**: 조합 중 입력이 끊기지 않는지 실제 입력으로 시험한다 (E2E 한계 → 수동 시험 항목, USER-TEST에 추가).
- 편집기 UI는 클라이언트 컴포넌트로 격리해 공개 사이트 번들에 들어가지 않게 한다.

## 7. 저장·충돌·임시저장

- **수동 저장**: 서버 액션 `save(id, version, data)`. `UPDATE ... WHERE id=? AND version=?`가 0행이면 **충돌**로 처리해 덮어쓰지 않고 "다른 곳에서 수정됨"을 알린다. 성공하면 `version+1`을 돌려준다.
- **자동 임시저장 (스토리)**: 입력 후 약 5초 쉬면 `draft` 상태로 저장. 이미 `published`인 글을 편집 중일 때는 **자동 저장이 공개 내용을 바꾸지 않도록** 별도 초안 영역(`draft_body` 등)에 저장하고, "발행"을 눌러야 반영한다. (구현 시 `stories`에 초안 필드를 둘지 별도 테이블로 할지 확정 — 열린 질문 §13.1)
- **상태 표시**: "저장됨 / 저장 중 / 저장 실패 / 충돌". 저장 중 들어온 입력은 다음 저장에 합친다 (직렬화 큐).
- **이탈 방지**: 변경이 있으면 `beforeunload`와 내부 이동 확인.
- **검증 오류**: 필드별 메시지를 서버가 돌려주고 필드 옆에 표시. 스키마는 `types/`의 단일 정의를 서버·폼이 공유한다 (DEVELOPMENT §).

## 8. 삭제와 휴지통

- 콘텐츠(스토리·투어·장비·후기·미디어)는 **소프트 삭제**: `deleted_at` 기록. 목록에서 사라지고 공개에서도 사라진다. 휴지통 화면에서 복원 가능.
- **30일 뒤 영구 삭제**: 매일 한 번 실행되는 정리 작업(Vercel Cron). 요청은 비밀 헤더로 보호하고, 실행 결과를 로그에 남긴다. 미디어는 DB 행 삭제 후 Blob 객체도 삭제한다 (Blob 삭제 실패 시 재시도 대상 표시).
- **신청·문의 개인정보**는 휴지통 없이 **즉시 영구 삭제(파기)** 가능. 삭제 전 대상과 "되돌릴 수 없음"을 확인하고 `audit_log`에 기록(개인정보는 남기지 않음).
- 사용 중인 미디어를 삭제하려 하면 사용처를 보여 주고 경고한다.

## 9. 미디어 (Vercel Blob)

- **업로드 경로**: 어드민 클라이언트가 서버 액션/라우트에서 **업로드 토큰을 받아 Blob에 직접 올린다** (서버리스 요청 본문 크기 제한 회피). 토큰 발급은 `requireAdmin()` 이후에만, 허용 MIME·최대 크기를 토큰에 지정한다. *(Vercel Blob 클라이언트 업로드의 현재 한도·방식은 구현 시 문서로 재확인)*
- **허용**: JPEG·PNG·WebP·AVIF, 크기 상한은 SECURITY §7의 값. SVG 업로드는 허용하지 않는다 (스크립트 포함 가능).
- **서버 후처리**: 업로드 완료 콜백에서 **실제 파일 형식 확인(확장자·헤더 신뢰 금지), 위치정보(EXIF) 제거, 긴 변 기준 리사이즈, WebP 변환**을 거친 뒤 `media`에 등록한다. 후처리가 끝나기 전에는 공개 화면에서 쓸 수 없다. *(처리 도구는 `sharp` 후보 — 라이선스·Vercel 런타임 호환은 구현 시 확인)*
- **공개 접근**: 공개 이미지는 Blob 공개 URL을 `next/image`로 제공한다. 파일명은 서버가 만든 임의 이름으로 저장해 원본 파일명 노출을 막는다.
- **alt 텍스트**: 대표 이미지는 alt가 없으면 공개 불가 (콘텐츠 `status` 전환 시 서버 검증).
- **유료 한도**: Hobby의 Blob 무료 한도를 넘지 않도록 업로드 크기를 제한한다. 한도·요금은 Pro 전환 시 확인 (INFRASTRUCTURE §6).

## 14. 콘텐츠 발행 관리

### 14.1 유형 정의

`content/types/<type>.ts` 하나가 한 유형의 모든 것을 정한다: 키, 메뉴 이름, 공통 필드 중 쓰는 것, `fields` 스키마(검증), 발행 전 점검 항목, 공개 화면 라우트와 구조화 데이터 종류. 새 유형 = 정의 파일 추가 + 공개 라우트 연결.

| 유형 | 키 | 공개 경로(안) | `fields` 예 |
| --- | --- | --- | --- |
| 스토리 | `story` | `/story/[slug]` | (공통만) |
| 영상 | `video` | `/films/[slug]` (**제안** — §28, SCREEN-SPEC §5.15) | video_url, duration, has_captions |
| 여행 추천 | `travel` | `/travel/[slug]` (공개 화면은 후속 — §27, 경로는 그때 확정) | region, season, level, budget, place, checked_on |

### 14.2 발행 상태와 전이

`draft`(임시저장) → `review`(검토 필요) → `scheduled`(예약) → `published`(발행) → `archived`(보관). 

| 전이 | 허용 | 비고 |
| --- | --- | --- |
| draft → review / scheduled / published | 예 | 발행 전 점검 통과 필요 (대표 이미지 alt, 요약 길이, 출처·AI 표기 확인) |
| review → draft / scheduled / published | 예 | 자동 생성 글은 반드시 여기를 거친다 |
| scheduled → draft / published | 예 | 예약 취소 = draft, 즉시 발행 가능 |
| published → draft / archived | 예 | 공개에서 내림. 주소는 404 |
| archived → draft | 예 | |
| 그 외 | 거부 | 서버가 전이 규칙으로 검증, 이력 기록 |

- 모든 전이는 `audit_log`에 남긴다(누가, 언제, 어디서 어디로).
- `published`인 글을 편집할 때는 초안 영역에 저장하고 발행으로 반영한다 (§7, 열린 질문 §13.1).

### 14.3 예약 발행

- 예약된 항목은 `publish_jobs`에 작업으로 기록한다. 주기 실행(Vercel Cron, 5분 간격 시작 — 플랜별 최소 간격과 한도는 구현 시 확인)이 `run_at <= now()`인 작업을 가져와 발행한다.
- **멱등**: 작업 선점(`pending→running`)을 조건부 UPDATE로 하고, 이미 `published`면 건너뛴다. 같은 작업이 두 번 와도 한 번만 발행.
- **실패**: 최대 3회 재시도 후 `failed`. 대시보드 알림(DASH-04)에 표시, 오류 종류만 기록(원문 메시지·개인정보 제외).
- 실행 요청은 비밀 헤더로 보호하고 어드민 세션과 무관하게 동작한다. 시각은 서버 기준 UTC 저장, 화면은 한국 시간(KST) 표시.
- 발행 시 공개 화면 캐시를 갱신한다(태그 기반 재검증). sitemap·JSON-LD가 새 글을 포함하는지 시험.

### 14.4 제작 방식과 자동화 원칙

- `origin`으로 직접 / AI 도움 / 자동을 구분하고 목록에서 거를 수 있게 한다. 공개 화면 표기 여부는 열린 질문(§13.6).
- **자동 입력은 사람 승인 없이 공개하지 않는다.** `/api/ingest`는 토큰 인증이며 항상 `draft` 또는 `review`로만 저장한다. 토큰은 허용 유형을 제한하고 해시만 저장하며 폐기할 수 있다. "승인 없이 자동 공개" 규칙은 기본 꺼짐이고, 켜려면 별도 설계·확인을 거친다.
- 자동 생성 글은 사실 정보(가격, 일정, 위치)에 **출처·확인일**이 없으면 발행 전 점검에서 막는다 (CONCEPT §7.5 "가상 예시 금지" 원칙).

- **저장소 어댑터** (`media/storage.ts`): `MEDIA_STORE=blob`(Vercel Blob, `BLOB_READ_WRITE_TOKEN` 필요) / `local`(개발·시험 전용, 운영에서는 선택되지 않음) / 미설정(업로드 닫힘). 저장 경로는 서버가 만드는 무작위 `media/YYYY/MM/<32자 16진수>.webp`이며 원본 파일명은 저장하지 않는다. 경로 형식을 벗어난 키는 어댑터가 거부한다. 로컬 이미지는 `/media-dev/...`로 보이며 운영 빌드에서는 404다(E2E로 확인).
- **고아 파일 방지**: 파일을 저장한 뒤 DB 기록이 실패하면 저장한 파일을 지운다.
- **데이터** (`media` 테이블, 마이그레이션 `0004_media`): `mime`은 `image/webp`만(DB 제약), 저장 경로 고유, `alt`는 비어 있을 수 있음(비어 있으면 "대체 텍스트 없음" 표시, 콘텐츠의 대표 이미지로 쓰려면 필요 — AD-5에서 발행 점검에 연결), 삭제는 `deleted_at`(소프트).
- **삭제와 사용 중 경고**: 삭제 함수는 `mediaUsageCount`가 0일 때만 진행한다. **지금은 이미지를 참조하는 콘텐츠가 없어 항상 0**이며, 콘텐츠(AD-5~6)가 미디어를 참조하게 될 때 이 함수를 실제 집계로 바꾼다. 파일 자체의 삭제(Blob 객체 제거)와 고아 파일 정리는 휴지통·정리 작업(AD-6)에서 한다 — 지금 삭제는 라이브러리에서 숨기기까지다.
- **활동 기록**: 업로드(크기·해상도 수치), 대체 텍스트 수정(길이만), 삭제를 남기고 파일명·대체 텍스트 내용은 남기지 않는다(시험으로 확인).
- **함께 고친 것**: AD-1의 2차 인증 등록 화면에서 폼 안에 로그아웃 폼이 들어 있던 오류(HTML 규칙 위반, 개발 서버의 hydration 경고로 발견).
- **미확인**: 실제 Vercel Blob 스토어에서의 업로드·삭제, Blob 무료 한도·요금(INFRASTRUCTURE §6.1). 연결은 소유자 작업이다.
- **미구현(후속)**: 이미지 크기별 변환본(썸네일), 드래그·붙여넣기 업로드, 여러 장 한 번에, 사용처 표시, 영상 링크 관리.

- **가상 데이터**: `DATABASE_URL`이 없을 때만 쓴다(로컬 개발·E2E). **배포 환경(`VERCEL`)에서는 절대 쓰지 않는다** — 설정이 빠지면 가상 글이 아니라 빈 목록이다.
- **캐시 갱신**: 발행·취소·보관·예약·삭제·수정 내용 반영 때 서버 액션이 `updateTag` + `revalidatePath("/", "layout")`을 부른다(`refreshPublic`). 크론은 새로 발행된 글이 있을 때 `revalidateTag` + 같은 경로 갱신. 갱신이 닿지 않아도 홈·목록·상세·사이트맵은 **5분마다** 새 값을 읽는다.
- **화면**: 상세는 5b의 `ContentBody`로 본문을 그리고(이미지·영상 포함), 검색 제목·설명이 있으면 메타에 쓴다(없으면 제목·요약). 카드 배경색은 주소에서 정해지는 장식 색이다(대표 이미지 선택은 후속). 요약이 비면 본문 앞부분 160자를 쓴다. 날짜는 한국 시간 기준.

- **확인한 것**: 단위·통합(공개 기준·정렬·한국 시간 날짜·요약 대체·본문 검사 실패 숨김·이미지·draft 비노출·유형 분리). **운영 빌드를 개발 DB(Neon)에 연결해 브라우저로 실제 조작 19개 항목**: 임시저장 글 404 → 지금 발행 후 상세·목록·홈·사이트맵 반영(첫 요청부터) → 수정 중에는 공개 제목 그대로 → 수정 내용 발행 후 변경 → 보관·삭제 후 404와 목록·사이트맵 제외 → 없는 주소 404 → 콘솔 오류 없음. 시험 데이터·계정은 삭제.

- **결정: 장비도 `contents`의 유형 `equipment`** (§5.2 의 별도 `equipment` 테이블 안을 바꾼다 — 투어와 같은 이유, §22). 마이그레이션 없음. 장비명 = 제목(60자), **한 줄 추천 이유 = 요약(100자, 발행 필수)**, **추천 이유 상세 = 본문(선택 — 비어 있어도 발행 가능)**. 유형 정의에 `titleMax`·`summaryMax`·`summaryRequired`·`bodyOptional`·화면 문구가 추가돼, 새 유형이 같은 방식으로 규칙을 선언한다.
- **장비 항목** (`content/equipmentFields.ts`, 순수 함수): 카테고리(20자), 브랜드(40자), 특징(8개, 각 60자, 빈 줄·중복 제거), 대표 이미지(발행 필수), 추가 이미지(0~6장, 대표와 같은 것·중복 제거), 가격대(40자), 정보 확인일(실제 날짜), 행동 유형(버튼 없음 / 구매처 링크 / 문의하기), 구매 링크(**https 만**, 계정 정보 없는 주소, 구매처 링크 유형일 때만 저장), 버튼 라벨(20자, 비우면 기본 "구매처 보기"/"문의하기"), 제휴 링크 여부, 노출 순서(0~9999, 비우면 100). 임시저장은 일부가 비어도 된다. **발행·예약 전**에는 한 줄 추천 이유·카테고리·대표 이미지가 있어야 하고, 구매처 링크 유형이면 링크가 있어야 하며, 대표·추가 이미지의 대체 텍스트가 모두 있어야 한다(본문·갤러리와 같은 규칙).
- **발행 상태는 공통 5단계를 쓴다**: SCREEN-SPEC 의 장비 "공개 / 비공개" 대신 임시저장·검토·예약·발행·보관을 그대로 쓴다(예약 발행·수정 초안까지 얻는다). "비공개"는 보관 또는 임시저장으로 되돌리기에 해당한다.
- **카테고리는 목록이 아니라 입력이다**(SCREEN-SPEC 의 "어드민에서 관리하는 목록에서 선택"과 다른 점): 이미 쓰는 카테고리는 입력할 때 고를 수 있고(`listEquipmentCategoryNames`), 새 이름을 쓰면 새 카테고리가 생긴다. 공개 칩은 **공개된 장비가 있는 카테고리만**, 목록 순서대로 처음 나온 순서로 만든다. **이름 바꾸기는 장비마다 고쳐야 한다** — 카테고리 관리 화면은 필요해지면 후속으로 만든다(태그·카테고리 단계).
- **공개 화면** (`data/equipmentQueries.ts` 질의, `data/equipment.ts` 입구): 스토리·투어(§21·§22)와 같은 규칙 — 발행됨 또는 예약 시각이 지난 예약만, 공개 내용은 본문 칸만(수정 중인 구매 링크·가격은 새지 않음), 본문은 읽을 때 재검사, 카테고리·한 줄 이유가 비었거나 깨진 장비는 숨김, 태그 캐시 `contents-equipment`(5분), 가상 데이터는 `DATABASE_URL`이 없을 때만(배포 환경에서는 절대 쓰지 않음). 순서는 **노출 순서가 작은 것 → 공개 시각이 최근인 것**. 대표 이미지가 삭제되면 장비는 숨기지 않고 자리표시로 보인다.
- **구매 링크의 안전**: https 만 받고(`javascript:`·`http:`·계정 정보가 든 주소는 거부), 외부 링크는 새 탭에서 열고 opener 를 끊는다(기존 SmartLink). **제휴 링크는 `rel="sponsored nofollow noopener noreferrer"`** 로 열어 검색엔진에 광고성 링크임을 알리고, 제휴 고지 문구가 함께 보인다(실제 확인). 구매처 링크가 아닌 유형으로 바꾸면 링크·제휴 표시는 공개에 나가지 않는다.
- **어드민 화면**: 전체 콘텐츠에 "새 장비" 만들기와 유형 필터. 장비 편집 화면에 장비 정보(카테고리·브랜드·특징·대표 이미지·추가 이미지·가격대·확인일·행동 버튼·구매 링크·버튼 라벨·제휴·노출 순서)가 더해지고, 요약·본문 이름은 "한 줄 추천 이유 (100자 이하)"·"추천 이유 상세 (선택)"이 된다. 갤러리 고르기 컴포넌트는 투어와 공유한다(설명 입력은 장비에서는 숨김).
- **미디어 사용 집계**: 대표·추가 이미지(공개 내용·수정 중인 내용 모두)로 쓰이는 이미지는 삭제할 수 없다. `Thumb` 일반 이미지 전환(§22) 덕분에 블롭 주소 설정 없이 대표 이미지가 보인다. `Button` 에 `rel` 지정이 추가됐다.
- **시험 중 발견한 실제 버그와 해결**: 행동 유형 선택칸을 **상태로 값을 쥐는(controlled) 선택칸**으로 만들었더니, 서버 액션이 끝난 뒤 React 19 가 폼을 되돌릴 때 **화면 값만 첫 항목("버튼 없음")으로 돌아가고 상태는 "구매처 링크"로 남아**, 구매 링크 입력칸은 보이는데 저장은 "버튼 없음"으로 되었다(구매 링크·버튼 라벨이 사라지고 제휴 표시만 남음, 개발 DB 에서 확인). 선택칸을 uncontrolled(`defaultValue`)로 바꾸고, 저장·오류 때마다 새로 만들어지는 조각(`ActionFields`, key)으로 분리해 화면·상태·서버 값이 항상 같게 했다. 대표 이미지 선택칸도 같은 구조로 바꿨다. **원칙: 이름이 있는(제출되는) 입력은 controlled 로 두지 않는다.** 같은 시험의 교훈: 오류 메시지가 뜬 직후 바로 입력하면 폼 되돌림과 겹쳐 입력이 지워질 수 있다(사람이 읽고 입력하는 속도에서는 문제가 되지 않아, 시험이 기다린 뒤 입력하도록 고쳤다).
- **확인한 것**: 단위·통합 311개(장비 항목 검증 12, 공개 조회 13, 어드민 저장·발행·이미지 사용·카테고리 9 포함). **운영 빌드를 개발 DB(Neon)에 연결해 브라우저로 실제 조작한 34개 항목**: 한 줄 추천 이유·상세 문구, 발행 점검(카테고리·대표 이미지, 본문은 비어도 통과), http 구매 링크 거부와 입력 유지, 추가 이미지 고르기·대체 텍스트 경고와 발행 차단, 저장한 값이 다시 열어도 그대로, 임시저장 비공개, 발행 후 상세(이름·이유·브랜드·가격·확인일·특징·대표 이미지)·목록·카테고리 칩·허브·사이트맵, **제휴 rel 과 고지 문구**, 문의하기 유형의 사이트 안 링크, 노출 순서, 수정 초안 분리와 반영, 보관·삭제 후 404 와 목록·사이트맵 제외, 유형 필터. 시험 데이터·계정은 삭제했다. (특징 중복 제거는 화면 HTML 에 데이터가 한 번 더 실려 글자 수 세기로는 확인할 수 없어, 저장된 값과 단위 시험으로 확인했다.)
- **미확인**: Vercel 배포 환경, 실제 이미지 파일이 있는 장비 화면(시험은 이미지 행만 만들었다)·썸네일 클릭 전환, 어드민 장비 편집 화면의 시각 확인(레이아웃·모바일 캡처), 한국어 입력(IME)·Safari·화면 읽기 프로그램, 제휴 고지 문구의 법적 적절성(사이트 설정의 문구 — 법률 검토 대상).
- **미구현(후속)**: 후기 DB 전환(6b 후기 PR — 동의 확인·수정 이력·투어 연결·대표 후기), 카테고리 이름 일괄 바꾸기, 장비 문의 폼(문의하기는 Contact 로 간다), 장비의 상품 구조화 데이터(제휴·가격 표기 위험이 있어 만들지 않음).

## 24. AD-6b(후기) 구현 기록 (0.31.0)

범위: 수강 후기를 어드민에서 만들고 공개·철회하며, 공개 후기 화면(후기 전체·홈·Freediving 허브·투어 상세)을 DB 로 전환. 6b 의 장비(§23)에 이어 6b 를 마무리하는 단계다. **이 단계는 DB 마이그레이션이 있다(0006, 운영 DB 에 먼저 적용해야 한다 — AGENTS §8).**

- **결정: 후기는 `contents`가 아니라 별도 테이블 `reviews` + `review_revisions`다** (§5.2 의 안 그대로). 이유: 후기는 제목·주소 이름·리치 본문이 없고, **"동의 확인 없이는 공개할 수 없다"를 DB 제약으로 강제**해야 하며, 수정 이력과 철회가 핵심이기 때문이다. 투어·장비와 달리 마이그레이션이 필요하다(새 표 2개만 추가, 기존 데이터에 영향 없음).
- **데이터** (`db/schema.ts`): `reviews` — 원문(1~1,000자), 수강생 표기(1~40자), 표기 방식(실명·이니셜·닉네임), 작성일(date), 출처(블루페블·인스타그램·직접 전달·기타)와 메모, 연결 투어(투어 콘텐츠의 주소 이름, 외래키 없음), 대표 여부·대표 순서(0~9999, 기본 100), **공개 동의 확인과 동의 메모**, 상태(비공개·공개), version, 삭제 시각. **`평점` 항목은 없다.** DB 제약: 원문·표기 길이, 표기 방식·출처·상태 값, **`status <> 'public' or consent_confirmed`**(동의 없이 공개 불가). `review_revisions` — 후기별로 그 시점의 내용 전체(snapshot)와 사유(만듦·수정·공개 전환·철회·삭제), 변경자, 시각.
- **입력 규칙** (`reviews/fields.ts`, 순수 함수): **원문을 가공하지 않는다** — 줄바꿈 형식(CRLF→LF)과 앞뒤 공백만 정리하고 안쪽 글자·띄어쓰기·맞춤법·HTML 처럼 보이는 글자는 그대로 둔다(탭·줄바꿈 말고 제어 문자는 거부). 작성일은 실제 날짜이고 **오늘(한국 시간)보다 뒤일 수 없다.** 연결 투어는 실제로 있는(삭제되지 않은) 투어여야 한다.
- **공개와 동의** (`data/admin/reviews.ts`): 후기는 **항상 비공개로 만들어진다.** 동의 확인이 체크돼 있어야 공개할 수 있다(서버가 먼저 막고 DB 제약이 한 번 더 막는다). **공개 중인 후기는 동의 확인을 해제할 수 없다**(철회를 쓰도록 안내). 공개 중인 후기를 고치면 **바로 공개 화면에 반영된다**(후기에는 수정 초안이 없다 — 오탈자 수정 등 가벼운 수정이 대부분이고, 고칠 때마다 이력이 남는다). 연결한 투어가 삭제됐으면 공개할 수 없다.
- **철회** ("철회 (즉시 비공개)"): 수강생이 공개를 원치 않을 때 **확인 없이 한 번에 즉시 비공개**로 돌리고 철회로 기록한다(SECURITY §8). 안전한 쪽으로 가는 작업이라 확인 단계를 두지 않았다. 완료 안내는 이동한 화면의 배너로 남는다(철회 패널이 사라지므로).
- **삭제**: 목록에서 숨기고 비공개로 돌린다. 수정 이력은 남는다. **복원과 영구 삭제는 휴지통(§25, 0.32.0)에서 한다 — 영구 삭제하면 수정 이력의 원문까지 지워진다.** 그 전까지 삭제한 후기의 원문은 수정 이력에 남아 있다 — 수강생이 완전한 삭제를 요청하면 6c 의 영구 삭제가 필요하다(개인정보 처리방침의 보관·파기 문구와 맞출 것).
- **공개 화면** (`data/reviewQueries.ts` 질의, `data/reviews.ts` 입구): **공개(public)이고 동의 확인이 된 후기만**(질의에서 한 번 더 건다), 삭제된 후기 제외. 공개 응답에는 화면에 필요한 값(원문·수강생 표기·작성일·연결 투어·대표 여부)만 있고 **동의 메모·출처·수정 이력은 읽지 않는다**(시험으로 확인). 태그 캐시 `reviews`(5분), 가상 데이터는 `DATABASE_URL`이 없을 때만(배포 환경에서는 쓰지 않음). 노출 규칙(INT-07): 후기 전체 = 작성일 역순, 홈·허브 = 대표 후기를 **대표 순서 → 최근 작성일 순으로 3건**, 투어 상세 = 연결된 공개 후기 최대 4건, 없으면 대표 후기 3건. 후기 카드의 투어 링크는 **지금 공개된 투어**일 때만 건다(6a·6b 의 투어 연결 미결 해소: 후기의 투어 필터·링크가 DB 투어를 쓴다).
- **원문을 화면에서도 그대로 보여 준다**: 후기 카드의 글을 `white-space: pre-wrap`으로 바꿨다(이전 `pre-line`은 연속 띄어쓰기를 한 칸으로 합쳤다). 글은 **글자로만 그린다** — `<script>`·`<b>` 같은 모양의 원문도 태그로 해석되지 않는다(실제 화면에서 확인).
- **어드민 화면**: 메뉴 "운영 > 수강 후기". 목록(공개 상태·투어·검색어로 거르기, 상태별 개수, 원문 앞부분 60자), 새 후기, 편집(원문 입력과 글자 수, 수강생 표기·표기 방식, 작성일, 연결 투어, 출처·메모, **공개 동의 체크와 동의 메모**, 대표 후기·순서), 공개/비공개 전환, 철회, 수정 이력(펼치면 그 시점의 원문과 상태), 삭제. 입력은 모두 uncontrolled 이고 저장·오류 때마다 새로 만들어진다(§23 원칙). 후기 화면에는 "수강생의 글이 담긴 화면" 안내를 둔다.
- **활동 기록에는 후기 내용·수강생 표기를 남기지 않는다**(만들기·수정·공개 전환·철회·삭제와 버전·상태만, 시험으로 확인). 서버 로그에도 오류 종류만 남긴다.

### About
- **데이터** (`db/schema.ts` `about`, 마이그레이션 0007): 행은 **하나뿐**(`id` 는 항상 `main`, DB 제약). 공개 내용 `headline`·`body`(본문 JSON)·`signature`·`photo_media_id` + 고치는 중인 내용 `draft`(JSON), `status`(draft/published), `version`, `published_at`. 새 표를 추가할 뿐 기존 데이터는 건드리지 않는다.
- **저장해도 공개되지 않는다 — "공개 반영"을 눌러야 공개된다.** 실제 이력·자격은 규강이 확인한 내용만 공개해야 한다는 CONCEPT §7.5 때문이다. 저장은 항상 `draft` 칸에 쌓이고, 공개 반영 때 공개 칸으로 옮겨진다. 공개 중인 About 을 고쳐도 반영 전까지는 공개 화면이 바뀌지 않는다("수정 내용 버리기"로 되돌릴 수 있다).
- **공개 반영 전 점검**: 헤드라인 필수, 본문 필수, 프로필 사진이 있으면 **대체 텍스트 필수**(없으면 막는다). 헤드라인은 두 줄·80자 이하(줄바꿈은 화면에서도 줄바꿈), 서명은 40자 이하(비우면 서명 없음). 본문은 스토리와 같은 편집기·허용 목록이고 서버가 다시 거른다. 삭제되었거나 없는 이미지는 저장되지 않는다.
- **공개 멈추기**: `/about` 이 기본 문구(확정 카피)로 돌아가고, 공개했던 내용은 수정 중인 상태로 남아 다시 쓸 수 있다.
- **공개 화면** (`data/aboutQueries.ts` 질의, `data/about.ts` 입구): **공개 중인 내용만** 읽고 수정 중인 내용은 읽지 않는다. 본문은 읽을 때 다시 검사하고, 통과하지 못하거나 헤드라인이 비면 null → 기본 문구. 사진은 대체 텍스트가 있고 삭제되지 않았을 때만 보인다. 태그 캐시 `about`(5분)이며 공개 반영·공개 멈추기 때 즉시 갱신된다. **공개된 내용이 없으면(처음 상태 포함) 지금 화면과 똑같은 기본 문구를 보여 주므로, 마이그레이션 뒤에도 공개 화면은 바뀌지 않는다.** 화면 본체는 `AboutView` 로 빼서 공개 화면과 어드민 미리보기가 같은 모양을 쓴다.
- **어드민 화면**: 메뉴 "사이트 > About". 헤드라인·본문 편집기·서명·프로필 사진 고르기·저장, 오른쪽 "공개 관리"(공개 전 점검 표시, 공개 반영, 수정 내용 버리기, 공개 멈추기), **수정 중인 내용 미리보기(새 탭)**. 공개 반영·버리기·멈추기는 화면을 다시 불러오며 위쪽 안내로 알린다(작업하면 버튼이 사라지므로 — §24 의 교훈). 입력은 모두 uncontrolled 이고 저장·오류 때마다 새로 만든다(§23 원칙).

### 태그·카테고리 관리
- **화면**: 메뉴 "콘텐츠 > 태그·카테고리". 글에 쓰인 태그 전부와 장비 카테고리 전부를 **쓰는 글 수**와 함께 보여 준다(휴지통의 글은 세지 않는다).
- **이름 바꾸기·합치기**: 새 이름을 쓰고 "바꾸기". **이미 있는 이름으로 바꾸면 두 이름이 합쳐지고**, 한 글 안의 중복은 하나가 된다. 태그는 20자 이하, 카테고리는 20자 이하(장비 규칙). 공개 내용(`tags`/`fields`)과 **수정 중인 내용(`draft`)에 함께** 반영된다.
- **태그 지우기**: 모든 글에서 그 태그만 빠진다(글은 그대로). 확인 체크가 필요하다. 카테고리는 장비를 발행하는 데 필요한 항목이라 **지우기는 없고** 이름 바꾸기·합치기만 한다.
- **안전장치**: 바뀐 글은 `version` 이 올라가 그 글을 열어 둔 편집 화면이 저장할 때 충돌 안내를 받는다. 글마다 조건부로 갱신하므로 그 사이 다른 곳에서 고쳐진 글은 건너뛰고 건수로 알린다("한 번 더 눌러 주세요"). 휴지통의 글은 건드리지 않는다. 변경 뒤 공개 캐시를 갱신해 공개 화면의 태그·카테고리도 바로 바뀐다.

## 27. AD-6d(영상·여행 추천) 구현 기록 (0.34.0)

범위: 콘텐츠 유형 **영상**(`video`)과 **여행 추천**(`travel`)을 **어드민에서** 만들고 임시저장·검토·예약·발행·보관·삭제(휴지통)·복원까지 쓸 수 있게 한다. 6d 가 이것으로 끝나고, AD-6 이 모두 끝난다. **이 단계는 DB 마이그레이션이 없다**(`contents` 의 `fields` 칸을 쓴다). 결정(사용자 선택): **어드민까지만 만들고 공개 화면은 만들지 않는다.** PRD 가 AI 영상 섹션을 Phase 1 에서 제외했고 두 유형의 공개 화면 시안(SCREEN-SPEC)이 아직 없기 때문이다.

- **공개 화면이 없다는 것을 어드민이 알린다**: 유형 정의의 `noPublicNote` 가 있으면 새로 만들기 칸 아래와 편집 화면 위에 "발행해도 사이트에는 나타나지 않고, 내용을 미리 준비해 두는 용도"라는 안내를 보여 준다. 그래서 `publicPath`(공개 경로)는 유형 정의에서 선택 항목이 되었고, 영상·여행 추천은 두지 않았다(§14.1 표의 `/videos`·`/travel` 경로는 공개 화면을 만들 때 확정한다).
- **영상 항목** (`content/videoFields.ts`, 순수 함수): 영상 주소(YouTube·Vimeo https 만, 시청 주소로 정규화 — 직접 업로드하지 않는다, PRD A-5), 길이(`3:25`·`1:02:30` 모양, 선택), 자막 여부. 제목은 80자, 영상 설명(요약)은 선택, 영상 소개(본문)도 **선택**이다. 발행·예약 전에는 **영상 주소가 있어야 한다.**
- **여행 추천 항목** (`content/travelFields.ts`, 순수 함수): 지역(30자)·장소(60자)·추천 시기(30자, 선택)·난이도(입문·중급·상급·정하지 않음, 선택)·예산 안내(60자, 선택)·정보 확인일(날짜, 선택 — 가격·시기는 오래되기 쉬워 둔다). 한 줄 소개(요약)와 추천 내용(본문)은 필수. 발행·예약 전에는 **지역·장소·한 줄 소개·본문이 있어야 한다.** 임시저장은 일부가 비어도 된다.
- **어드민 화면**: 전체 콘텐츠에 "새 영상"·"새 여행 추천" 만들기 칸과 유형 필터가 생겼고, 편집 화면에 유형별 입력(`VideoTravelSections.tsx`)이 더해진다. 입력은 모두 uncontrolled 이고 저장·오류 때마다 새로 만든다(§23 원칙) — 난이도 선택과 자막 체크가 저장 뒤에도 유지되는 것을 실제 화면에서 확인했다. 휴지통에는 "영상"·"여행 추천"으로 표시된다.
- **공개 누출 방지**: 공개 조회는 모두 유형을 거르므로(스토리·투어·장비) 발행된 영상·여행 추천은 어떤 공개 화면·사이트맵·홈에도 나오지 않는다. 시험으로 확인했다(발행해도 스토리·투어·장비 조회에 섞이지 않음, 공개 주소 404).
- **함께 고친 것**: 삭제 안내 문구가 "휴지통에서 복원하는 기능은 다음 단계에서 추가됩니다"로 남아 있었다(휴지통은 0.32.0 에서 이미 만들었다). 콘텐츠·후기 삭제 안내를 "30일 안에는 어드민의 휴지통에서 복원할 수 있습니다"로 고쳤다. (사이트 설정 화면의 "다음 단계에서 추가" 문구는 사이트 설정 문구의 DB 연결이 아직 안 되어 사실이라 그대로 둔다.)
- **확인한 것**: 단위·통합 400개(이번 추가 10 + 기존 시험 갱신 1: 영상 주소·길이·자막·발행 점검, 여행 항목 검사·난이도·점검, 영상은 본문 없이 주소만 있으면 발행·여행 추천은 지역·장소·소개·본문이 있어야 발행, **발행된 영상·여행이 스토리·투어·장비 조회에 섞이지 않음**). **운영 빌드를 개발 DB(Neon)에 연결해 브라우저로 실제 조작한 30개 항목**: 만들기 칸·안내·필터, 영상(허용 밖 주소 거부·입력 유지·저장 뒤 자막 유지·발행), 여행 추천(점검 → 본문 없이는 발행 안 됨 → 본문 후 발행·난이도 유지), 사이트맵·스토리·Freediving·투어·장비·홈에 안 섞임과 공개 주소 404, 삭제 → 휴지통 "영상" 표시 → 복원(임시저장), 활동 기록에 영상 주소·지역 없음. 시험 데이터·계정은 삭제했다. (스크립트 문제 세 가지를 앱의 오류로 오해하지 않도록 확인했다: 오류 직후 폼이 다시 만들어지는 동안의 입력, 문서 안 문구 "발행됨"을 상태로 착각한 대기, 새로고침 직후 눌러 반응이 없던 것 — 모두 앱 동작은 정상이었다.)
- **미확인**: Vercel 배포 환경, 새 입력 화면의 시각 확인(모바일 포함), 한국어 입력(IME)·Safari·화면 읽기 프로그램, 실제 YouTube·Vimeo 주소의 재생(어드민은 주소 형식만 확인한다 — 공개 화면이 없다), 두 유형의 미리보기(지금 미리보기는 제목·요약·본문만 보여 주고 유형별 항목은 보여 주지 않는다).
