| 문서 버전 | 최종 수정 | 상태 | 작성 |

검색 노출(SEO)·생성형 검색 노출(GEO) 작업을 **어느 기기에서든 같은 방식으로 이어 가기 위한** 문서다. 무엇을 왜 하는지(계획)는 [SEO-GEO.md](SEO-GEO.md), 규강이 따라 하는 등록 순서는 [검색엔진 등록 안내](../operations/2026-11-28-search-engine-registration.md)에 있다. 이 문서는 그 둘 사이의 **작업 방법·현재 상태·할 일·다음 순서**를 모은다.

## 1. 새 기기에서 시작하기

### 1.1 저장소와 앱

```bash
git clone https://github.com/diverkyu/personal-branding.git
cd personal-branding/app
npm ci
```

- `app/.env.local` 이 필요하다(커밋 금지). 키 이름은 [`app/.env.example`](../../app/.env.example)에 있다. **값은 Neon `dev` 브랜치·Vercel Preview 환경의 것만** 쓴다(AGENTS §8). 값을 문서·대화·PR 에 쓰지 않는다.
- `SITE_INDEXING` 은 로컬에서 비워 둔다. 로컬·프리뷰는 어드민 스위치와 관계없이 검색엔진이 막힌다.
- 시험 데이터가 필요하면 `npm run dev:seed`(dev DB 전용).

### 1.2 Claude Code 준비

| 항목 | 방법 |
| --- | --- |
| 작업 규약 | 저장소 루트 `AGENTS.md` 를 먼저 읽는다 (Claude 는 `CLAUDE.md` 가 자동으로 불러온다) |
| 보안 점검 플러그인 `security-guidance` | 저장소 `.claude/settings.json` 이 켠다. `claude plugin list` 에서 `✔ enabled` 확인 (AGENTS §9) |
| 디자인 플러그인 `frontend-design` | 위와 같음. 공유 이미지 등 새 화면 작업 때만 쓴다 (AGENTS §10) |
| **geo-index · geo-text 스킬** | 저장소에 **없다**(재배포 금지 조건, PRD §10). 스폰지클럽 스타트킷의 `1_이니_GEO` 폴더에서 `cp -R geo-text geo-index ~/.claude/skills/` 로 기기마다 설치한다. geo-index 는 Node 18+ 와 설치된 크롬이 필요하다 |

### 1.3 GitHub 작업 방식

- `main` 에 직접 푸시하지 않는다. 최신 `main` 에서 브랜치(`feat/seo-…`, `docs/seo-…`, `fix/seo-…`) → PR → **병합은 사람이**(규강·Lucia). 한 단계 = PR 하나, 앞 PR 이 병합된 뒤 다음 브랜치를 판다(AGENTS §7).
- `gh` CLI 를 쓰지 않는 기기면 브라우저의 compare 화면에서 PR 을 연다: `https://github.com/diverkyu/personal-branding/compare/main...<브랜치>?expand=1`
- PR 본문에는 **통과 / 실패 / 미검증 / 대기**를 나눠 쓰고, `보안 점검(security-guidance)` 줄을 둔다. 화면이 바뀌면 390/768/1440 전후 캡처.
- 코드가 명세를 바꾸면 같은 PR 에서 `docs/phase1/` 문서와 [CHANGELOG](CHANGELOG.md)·문서 세트 버전을 함께 올린다.
- 공통 게이트: `npm run check`(타입·린트·단위·빌드), 화면이 바뀌면 `npm run test:e2e`.
- 커밋할 때는 바꾼 파일만 골라 `git add <파일>` 한다. 폴더째 `git add` 하면 로컬에서 지운 파일까지 들어간다(2026-11-28 #72 에서 실제로 있었음).

## 3. 전체 페이지 SEO 점검 (2026-11-28, 운영)

**방법**: 운영 사이트맵의 15개 주소 + 사이트맵에서 뺀 2개(장비·후기 목록)를 받아, 서버가 처음 보내는 HTML 에서 상태 코드·제목·설명·정규 주소·공유 미리보기·h1·언어·구조화 데이터·이미지 대체 텍스트를 읽었다. 검색 노출은 아직 꺼져 있어(`noindex`, robots `Disallow: /`) 실제 검색 결과는 볼 수 없다.

## 4. SEO 자동화 — 점검을 습관이 아니라 도구로

사람이 매번 들여다보지 않게 **세 겹**으로 만든다. 순서대로 PR 하나씩.

### 4.1 E2E 에 SEO 규칙 넣기 (배포 전 막기)

`tests/e2e/seo.spec.ts`(새 파일) — 모든 공개 경로(사이트맵에 나오는 종류별 대표 주소)에서 아래를 검사한다. `npm run test:e2e` 에 포함되어 PR 마다 돈다.

- 상태 200, `lang="ko"`, h1 정확히 1개
- `<title>` 있음·비어 있지 않음·사이트 안에서 겹치지 않음 (상세는 글 제목 포함)
- `meta description` 있음, 40~160자, **기본 설명과 같은 화면이 목록 화면에서 없어야 함**(3.2-1 이후 켜기)
- canonical = 자기 경로(필터 쿼리 없음), 사이트맵 표기와 같음
- og:title·og:description·og:url·og:site_name·og:locale, og:image(3.2-2 이후 켜기)
- 구조화 데이터가 JSON 으로 파싱되고, 종류별 필수 칸이 있음(Event: name·startDate·location, Article: headline·datePublished, VideoObject: name·thumbnailUrl·uploadDate)
- 사이트맵의 모든 주소가 200 이고 `noindex` 가 아님(노출이 켜진 설정으로 띄운 시험 서버 기준)
- 의미 있는 이미지에 대체 텍스트

이미 있는 시험: `foundation.spec.ts`(정규 주소·사이트 이름·Person), `elements.spec.ts`(구조화 데이터 일부). 새 파일은 이것을 모든 경로로 넓힌다.

### 4.2 운영 점검 명령 (배포 후 확인)

`app/scripts/seo-audit.mjs` + `npm run seo:audit -- https://www.diverkyu.com` — 운영 사이트맵을 받아 4.1 과 같은 규칙으로 HTML 을 읽고 **표로 출력**한다(이 문서 §3 을 만든 방법을 스크립트로 고정). 의존성 없이 Node 내장 `fetch` 만 쓴다. 결과에 개인정보가 없으므로 PR·운영 기록에 붙여도 된다.

- 언제: 공개 직후, 새 종류의 페이지를 만든 뒤, 한 달에 한 번
- 규강이 노출을 켠 뒤에는 `REMOTE_EXPECT_INDEXING=on npm run test:remote` 도 함께(노출 상태·보안 헤더)

### 4.3 정기 실행 (선택 — 규강 결정 필요)

| 방법 | 장점 | 필요한 것 |
| --- | --- | --- |
| GitHub Actions 주 1회(`schedule`) — `seo:audit` 결과를 Actions 요약에 남기고, ✕ 가 있으면 이슈를 연다 | 사람이 안 해도 돈다. 기록이 GitHub 에 남는다 | 저장소에 워크플로 파일 추가(저장소 소유자 규강 승인), 비밀값 없음 |
| 매달 작업자가 `npm run seo:audit` 를 돌려 운영 기록에 붙이기 | 설정 없음 | 사람이 기억해야 함 |

검색 순위·클릭 같은 **실제 성과**는 도구가 아니라 구글 서치콘솔 "실적"·네이버 서치어드바이저 "검색 반영"에서 본다(로그인은 규강).

### 4.4 새 글을 알리는 일

- 공개하면 사이트맵에 5분 안에 자동으로 들어간다(대부분 충분).
- 중요한 새 글만 geo-index 의 `request <주소>`(요청 전 점검 포함) 또는 각 콘솔에서 직접 요청. 같은 글 반복 요청 금지.
- IndexNow(빙·네이버 즉시 알림)는 선택. 키 파일을 사이트에 올리고 발행 때 알리는 개발이 필요하며 효과는 보장되지 않아 우선순위가 낮다.

## 8. 점검 기준 (페이지를 새로 만들 때)

- `pageMeta(경로, { title, description, openGraph })` 로 메타를 만든다 — canonical·공유 미리보기 기본값이 함께 들어간다(SEO-GEO §3).
- 제목: 상세는 글 제목, 목록은 "무엇의 목록인지 + 검색어" — 끝에 `— KYU` 가 자동으로 붙는다.
- 설명: 40~160자, 그 화면에만 맞는 한두 문장. 기본 설명을 그대로 두지 않는다.
- 공유 이미지: 상세는 대표 이미지, 없으면 기본 공유 이미지.
- 구조화 데이터는 화면에 보이는 내용만(가격 없는 투어에 `offers` 를 만들지 않는 등, DESIGN-SYSTEM §9).
- 빈 목록·임시 화면은 사이트맵에 넣지 않는다.
- 새 공개 경로는 `app/sitemap.ts` 와 E2E SEO 규칙 목록에 함께 추가한다.
