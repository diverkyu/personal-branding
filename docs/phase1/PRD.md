## 1. 배경과 목표

이동규(KYU, 이하 규강)는 프리다이빙 강사이자 AI 영상 크리에이터다. 기존 시안(`personal-branding` v0.1.0)은 정적 HTML이며 콘텐츠가 전부 코드에 박혀 있고, 문의는 `mailto:`뿐이다. diverkyu.com은 이를 **규강이 직접 콘텐츠를 발행·관리하는 사이트 + CMS 어드민**으로 확장한다.

**Phase 1 목표**: 프리다이빙 섹션(투어·장비·수강 후기)과 개인 스토리 섹션을 구축한다. AI 영상(Films)은 Phase 2 이후다.

**성공 기준 (Phase 1 종료 시)**
1. 규강이 코드 수정 없이 어드민에서 스토리·투어·장비·후기를 등록/수정/삭제할 수 있다.
2. 방문자가 투어 신청/문의를 사이트에서 제출하고, 규강이 어드민에서 확인할 수 있다.
3. 지난 투어가 후기·갤러리와 함께 아카이브로 노출된다.
4. 모바일에서 모든 공개 페이지를 읽고 폼을 제출할 수 있다.
5. **웹사이트로 공개(게시)된다.** 호스팅 방식은 열린 결정이다(§12). 도메인은 가칭(diverkyu.com)이며, 나중에 바뀌어도 코드 수정 없이 대응할 수 있다.

## 3. 범위

**Phase 1 포함**: 스토리, 투어(+신청 폼), 장비, 수강 후기, 어드민, 공개 사이트 레이아웃(홈·내비게이션·푸터 포함), 기본 SEO.

**Phase 1 제외**: AI 영상 섹션, 결제/이커머스 구매(구조만 확장 가능하게), 회원가입/방문자 로그인, 댓글, 다국어, 뉴스레터 발송.

## 5. 비기능 요구사항

- **성능**: 모바일에서 LCP 2.5초 이내 지향. 이미지 반응형/지연 로딩.
- **개인정보**: 신청 폼은 최소 수집(이름·연락처·이메일), 수집·이용 동의 체크 필수, 보관 기간과 파기 방침 명시. 관리자 외 열람 불가.
- **보안**: 어드민 인증, 서버측 입력 검증, 업로드 파일 형식·용량 제한, 신청 폼 스팸 방어.
- **운영 부담**: 1인 운영 기준. 서버 관리 부담이 작은 호스팅을 우선한다. **호스팅 방식은 아직 정하지 않았다**(§12, Vercel은 후보 중 하나).
- **배포 환경 제약(서버리스형 호스팅을 고를 경우)**: 서버의 로컬 디스크에 업로드 파일이나 DB를 저장할 수 없다. 그 경우 이미지는 외부 객체 스토리지, 데이터는 관리형 DB를 쓴다. 호스팅 결정 시 확정한다.
- **개발·보안 지침 준수**: 모든 변경은 [DEVELOPMENT.md](DEVELOPMENT.md)의 증거 우선 변경 루프(로그와 실제 브라우저 확인)와 [SECURITY.md](SECURITY.md)의 통제를 따른다. 인증·권한·업로드·공개 폼 변경은 SECURITY §15 시나리오를 통과해야 한다.
- **도메인 독립성**: 사이트 주소(`SITE_URL`)는 환경변수 한 곳에서만 정의하고, canonical·sitemap·OG·JSON-LD·메일 링크가 이 값을 참조한다. 주소를 코드에 하드코딩하지 않는다.
- **확장성**: 장비의 구매 연동, Phase 2의 Films/AI 섹션이 같은 구조에 얹힐 수 있게 한다.

### 10.1 키트의 성격

키트는 **Claude Code 스킬과 프롬프트·체크리스트 문서 묶음**이다. Next.js 앱 같은 곳에 끼워 넣는 코드 모듈이 아니다. 특히 케이의 "블로그 자동화"는 **네이버 블로그**에 글을 올리는 작업 흐름(도구 지도, 마스터 프롬프트)이라, 우리 CMS의 발행 기능으로 그대로 옮길 수 있는 코드는 없다.

### 10.2 이용 조건 → 파일은 저장소에 복사하지 않는다

- 키트는 스폰지클럽 안에서 공유되는 **학습용**이며, 키트 파일과 수정본을 **저장소 밖으로 배포하는 것**이 금지된다.
- 이니 `LICENSE`: 스킬과 수정본의 재배포·게시·판매 금지, 저작자 표시 유지. 결과물(기획·글·리포트)은 상업 이용 가능.
- 키트로 시작해 **새로 만든 내 워크플로우**는 개인 상업 작업에 써도 되고, 공개할 때 출처를 밝힌다. 예: `스폰지클럽 워크플로우 스타트킷 · 이니의 키트에서 시작했어요`.

따라서 diverkyu GitHub 저장소(공동 작업자 접근)에 키트의 파일을 복사하지 않는다. **아이디어와 방식을 우리 구조로 새로 구현**하고, 코드/문서에 출처를 남긴다. geo-text/geo-index는 `~/.claude/skills/`에 설치해 **개발 도구로만** 쓴다.

## 11. 저장소·브랜치 전략 (제안)

규강과 동시에 작업하므로 충돌을 구조로 막는다.

- **같은 `personal-branding` 저장소에서 작업하되 경로를 분리한다.** 기존 시안 `dist/`와 규강의 문서(`docs/*.md`)는 건드리지 않는다.
  - 새 앱: `app/` (자체 `package.json` 포함). 루트 `package.json`·`README.md`·`CHANGELOG.md`·`.gitignore`는 충돌이 잦으니 꼭 필요할 때 별도의 작은 PR로만 수정한다.
  - 새 문서: `docs/phase1/` (기존 `docs/`와 파일명이 겹치지 않게)
- **`main`에 직접 커밋하지 않는다.** 기능 단위 브랜치 → PR → 규강 검토 후 병합. 브랜치명 예: `feat/phase1-docs`, `feat/phase1-schema`.
- **용어 정합성**: 규강의 `PRODUCT-CONCEPT.md`는 메뉴를 `Dive · Films · About · Contact`로 제안했고, 이 문서는 `About · Story · Freediving · Contact` 순서다. 병합 전에 하나로 맞춘다. (제안: Dive = Freediving 허브. Films는 Phase 2)

### 12.3 게시 전 체크리스트 (R4 → R5)

- [ ] 모든 공개 페이지가 모바일과 데스크톱에서 보이고 폼 제출이 된다
- [ ] **Vercel을 Hobby에서 Pro로 전환했다** (Hobby는 비상업 개인 용도 전용, 투어 모집·제휴 링크는 상업적 사용 — [INFRASTRUCTURE.md §2](INFRASTRUCTURE.md)). Neon 무료 플랜의 상업 사용 가능 여부를 약관으로 확인했다
- [ ] 프로덕션 환경변수가 모두 설정돼 있고 프리뷰 값과 섞이지 않았다
- [ ] 코드와 콘텐츠에 가칭 도메인이 하드코딩돼 있지 않다 (`SITE_URL`만 참조)
- [ ] `/admin`은 비로그인 접근이 막히고 검색 색인에서 제외된다
- [ ] 임시저장 글과 비공개 후기·장비가 공개 페이지, sitemap, 검색 결과에 나오지 않는다
- [ ] 투어 신청 폼: 동의 체크, 스팸 방지, 규강 수신, 개인정보 문구 확인
- [ ] sitemap.xml, robots.txt, 페이지별 title·description·OG 이미지
- [ ] 후기 4건은 작성자 공개 동의와 표기 방식 확인 후 게시
- [ ] 제휴 링크가 있다면 고지 문구 노출
- [ ] 도메인 연결 후 HTTPS 정상, 리다이렉트 정상

### 12.4 도메인이 바뀔 때

가칭 도메인은 바뀔 수 있으므로 다음 절차를 미리 정한다.

1. 새 도메인을 Vercel 프로젝트에 추가하고 DNS를 설정한다.
2. 프로덕션 `SITE_URL`을 새 주소로 바꾸고 재배포한다. canonical, sitemap, OG, JSON-LD가 한 번에 바뀐다.
3. 이전 도메인은 새 도메인으로 영구 리다이렉트(301/308)한다. Vercel 프로젝트 도메인 설정에서 리다이렉트를 지정할 수 있다.
4. 서치콘솔·서치어드바이저에서 새 도메인을 등록하고 주소 변경을 안내한다.
5. 메일 발신 도메인(SPF/DKIM 등)과 SNS 프로필·명함 등의 링크를 갱신한다.

### 12.5 확인이 필요한 사항 (R0)

| 항목 | 이유 |
| --- | --- |
| **호스팅 선택** | 열린 결정. 후보와 선택 기준은 §12.1. 아래 Vercel 관련 항목은 Vercel을 고를 경우에 해당 |
| 계정 소유자 | 저장소는 `diverkyu` GitHub 계정에 있고 작업자가 둘이다. 누구 계정(팀)으로 프로젝트를 만들지, 서로 어떤 권한을 가질지 정해야 한다 |
| 요금제 | 무료(Hobby) 플랜의 사용 조건과 한도가 이 사이트(투어 모집 등 영업 성격, 두 명 협업)에 맞는지 Vercel 공식 요금 문서로 확인해야 한다. 이 문서에서는 확인하지 못했다 |
| 프리뷰 접근 보호 | 프리뷰 URL이 공개되면 미완성 콘텐츠와 테스트 데이터가 노출된다. 프리뷰 접근 제한 설정과 요금제별 제공 범위를 확인해야 한다 |
| 도메인 | 가칭 도메인의 보유·등록처, DNS 관리 주체. 아직 없다면 최종 도메인 확정 시점 |
| 기술 스택 | Vercel에서 지원되는 프레임워크, DB, 이미지 스토리지, 메일 발송 서비스의 조합 (스키마 제안서에서 비교) |
| 기존 Sites 배포 | v0.1.0 비공개 시안(`.openai/hosting.json`)을 게시 후에도 유지할지 |

### 12.6 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 서버리스 제약을 늦게 발견 | 이미지 업로드·파일 저장 설계 재작업 | R1~R2에서 스토리지와 DB를 먼저 연결해 본다 |
