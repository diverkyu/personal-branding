# Story 썸네일 연결

- 기록일: 2026-11-20 작성, 2026-11-21 정리(PR #52 병합 뒤 충돌 해결).
- 이 문서는 **운영 기록**이다. 코드 구현은 아래 "구현 경과"의 PR #52(v0.53.0)가 담당하며, 이 PR(#51)은 충돌 해결 뒤 **이 기록 문서와 README 링크만** 병합한다.

## 관측

- 사용자 요청: ‘내 방의 문을 열면 판타지 세계가 펼쳐진다면?’에 제공한 `환상속으로.png`를 썸네일로 사용.
- 운영 어드민에 이미지를 올리고 WebP 변환 성공을 확인했다. 대체 텍스트는 ‘환상속으로 — 거대한 바위 아치와 청록색 바다를 바라보는 인물의 뒷모습. Step into my imagination.’이다.
- 당시 Story 편집기에는 대표 이미지를 정하는 칸이 없었고, 목록 조회·카드 매핑도 이미지를 전달하지 않았다. **단순 업로드로는 썸네일이 나오지 않는다**(원인은 버그가 아니라 빠진 기능).
- 근거: PRD S-1·S-5, SCREEN-SPEC STORY-03·04.

## 구현 경과 (중요)

같은 기능이 두 갈래로 동시에 구현되었다.

| | PR #51 (이 PR, **코드는 제외하고 기록만 병합**) | PR #52 (**병합됨, 채택**) |
| --- | --- | --- |
| 필드 | `fields.thumbMediaId` | `fields.coverMediaId` |
| 고르는 방식 | 미디어 전체 목록에서 선택 | **그 글의 본문에 넣은 이미지 중에서** 선택 (네이버 블로그 방식). 고르지 않으면 첫 이미지 |
| 본문에서 이미지를 빼면 | (해당 없음) | 저장할 때 대표에서 자동 제외 |

운영자 결정(2026-11-21)에 따라 **#52 방식을 유지**하고, #51의 코드는 충돌 해결 때 제외했다. 두 방식이 같은 파일을 고쳐서 합칠 수 없었고, #52가 먼저 병합되었다. 설계와 검증은 [ADMIN-DESIGN §41](../phase1/ADMIN-DESIGN.md), CHANGELOG 0.53.0을 본다. DB 마이그레이션은 어느 쪽도 필요 없다.

> 한 가지 차이: #52 방식은 **본문에 넣지 않은 이미지는 대표로 고를 수 없다.** 본문에 쓰지 않는 표지 이미지가 필요하면 후속으로 "미디어에서 직접 고르기"를 더할 수 있다(운영자와 협의).

## 배포 후 해야 할 일 (#52 기준으로 고침)

원래 이 문서에는 "스토리 대표 이미지 고르기"에서 고른다고 적혀 있었으나, 실제 화면은 다르다.

1. PR 병합과 Production 배포 완료를 확인한다. (#52는 병합되었다. 배포 상태는 Vercel에서 확인.)
2. 해당 Story 편집기의 본문에 위 대체 텍스트의 이미지가 **들어 있는지** 본다. 없으면 편집기의 이미지 버튼으로 이미 올린 이미지를 골라 본문에 넣는다.
3. 본문 아래 **"대표 이미지"** 칸에서 그 이미지를 눌러 정한다. (고르지 않으면 본문의 첫 이미지가 대표가 된다.)
4. 저장한 뒤, 이미 발행된 글이면 **"수정 내용 발행"**을 누른다. 저장만으로는 공개 화면이 바뀌지 않는다.
5. 홈과 Story 목록의 썸네일을 확인한다. 세로 이미지가 가로 카드에 맞춰 잘릴 수 있으므로 화면 구도를 함께 본다.

이미지 업로드만 완료했으며, 운영 썸네일 적용 완료를 뜻하지 않는다. 비밀번호·토큰·DB 연결 문자열은 기록하지 않는다.
