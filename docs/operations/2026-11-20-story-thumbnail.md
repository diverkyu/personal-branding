# Story 썸네일 연결

## 관측과 수정

- 사용자 요청: ‘내 방의 문을 열면 판타지 세계가 펼쳐진다면?’에 제공한 `환상속으로.png`를 썸네일로 사용.
- 운영 어드민에 이미지를 올리고 WebP 변환 성공을 확인했다. 대체 텍스트는 ‘환상속으로 — 거대한 바위 아치와 청록색 바다를 바라보는 인물의 뒷모습. Step into my imagination.’이다.
- 기존 Story 편집기에 대표 이미지 입력이 없었고, 목록 조회·카드 매핑도 이미지를 전달하지 않았다. 단순 업로드로는 썸네일이 나오지 않는다.
- 근거: PRD S-1·S-5, SCREEN-SPEC STORY-03·04. 기존 이미지 선택기를 Story에도 재사용하고 선택 이미지를 홈·Story 목록 카드에 연결한다.
- 저장 위치는 기존 유형별 `fields.thumbMediaId`이다. DB 마이그레이션은 필요 없다. 본문 이미지는 변경하지 않는다.
- 대표 이미지는 선택이며 미지정·삭제된 이미지에는 기존 배경을 유지한다. 저장 시 존재 확인, 발행 시 대체 텍스트 확인, 사용 중 삭제 방지 및 수정 초안 분리를 기존 공통 경로로 적용한다.

## 배포 후 해야 할 일

1. PR 검토·사람의 병합과 Production 배포 완료 확인.
2. 해당 Story 편집기에서 ‘스토리 대표 이미지 고르기’로 위 대체 텍스트의 이미지를 선택.
3. 저장 후 ‘수정 내용 발행’ 실행.
4. 홈과 Story 목록의 썸네일 확인. 세로 이미지가 가로 카드에 맞춰 잘릴 수 있으므로 화면 구도를 함께 확인한다.

이미지 업로드만 완료했으며, 현재 운영 썸네일 적용 완료를 뜻하지 않는다. 비밀번호·토큰·DB 연결 문자열은 기록하지 않는다.

## 검증 결과

- 통과: TypeScript 검사, ESLint, Vitest 47개 파일·524개 테스트, 운영 빌드.
- 회귀 검사: 기존 빈 필드 호환, 잘못된 이미지 id 거부, 수정 초안 표지 비노출, 삭제된 이미지 대체 배경.
- 로컬 제한: 첫 빌드는 Windows junction 생성 권한으로 실패했으며, 권한을 허용한 동일 빌드는 통과했다.
- 미검증: 새 선택기의 로그인된 Preview 화면, 390/768/1440 화면 비교, 운영 카드의 실제 이미지 구도.
- 대기: 사람의 PR 병합·배포 후 이미지 지정과 수정 내용 발행. 운영 업로드 성공은 확인했으나 썸네일 표시 완료로 보고하지 않는다.
