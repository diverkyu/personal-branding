# SEO 어드민 1-1 운영 반영

2026-11-28 KST. 사용자 PR #78 병합 및 운영 반영 승인에 따른 기록. 근거: PRD A-10/ADM-SEO, SEO-INTELLIGENCE 1-1. 앱 코드와 마이그레이션 파일은 변경하지 않았다.

## 배포와 원인

- 원격 main `671fed2`에서 PR #78 병합을 확인했다. Vercel Production 배포 `GR1zxaj58kGP9i7AfznbWAaoBqcV`는 같은 커밋으로 **Ready**, 운영 도메인에 연결되어 있었다. 추가 재배포는 하지 않았다.
- 최초 운영 SEO 일지 진입에서 저장소 읽기 오류를 재현했다. Neon production의 적용 이력은 9개(0000~0008)였고 SEO 테이블 3개가 없었다. 코드 자동 배포와 DB 적용이 별개인 데서 발생한 오류다.
- 다음 스키마 변경은 운영 DB 적용과 상태 확인을 먼저 마치고, 그 스키마를 사용하는 코드를 배포한다. 이번 배포가 먼저 진행된 경위와 복구를 정상 순서로 일반화하지 않는다.

## 운영 DB 조치와 검증

- Neon 프로젝트의 production 기본 브랜치와 `neondb` 선택을 확인했다. Backup & Restore에서 **6시간 시점 복구 창**이 활성화된 것을 확인했다. 별도 스냅샷 생성·복원 시험은 하지 않았다.
- 기존 9개 마이그레이션의 시각과 SQL 해시를 저장소와 대조했다. Windows CRLF와 LF의 차이를 고려한 LF 해시가 모두 일치했다.
- 변경하지 않은 `0009_amusing_enchantress.sql`의 DDL(테이블 3개·인덱스 1개)과 Drizzle 적용 이력 행을 Neon SQL Editor에서 하나의 트랜잭션으로 반영했다. 연결 문자열·인증 키를 추출하거나 로컬에 저장하지 않았다.
- 트랜잭션에는 5초 lock timeout, 60초 statement timeout, 마이그레이션 이력 테이블의 배타 잠금과 기존 9개/최신 적용 시각 확인을 넣었다. 기존 콘텐츠·계정·설정 행을 수정하거나 삭제하는 SQL은 없다.
- 적용 후 별도 SELECT로 **마이그레이션 10개, SEO 테이블 3개, 인덱스 1개**를 확인했다. 0009의 기록 시각은 `1795863038986`, LF SHA-256은 `d192d78f319845fd750088e9dad74b8b56bc4bb093226e8c67eea25a177d01de`로 일치했다.
- 콘텐츠 전체 행 11개, 관리자 계정 행 2개, 사이트 설정 행 9개가 적용 전후 동일했다. 이는 행 수 보존 확인이며 모든 필드에 대한 체크섬 비교는 아니다. 콘텐츠 UI의 활성 발행 항목 7개와 DB 전체 행 수는 집계 범위가 다르다.
- CLI `npm run db:status`를 실행한 것으로 표시하지 않는다. 이번 운영 검증은 Console의 읽기 전용 SQL과 저장소 해시 비교로 수행했다.
