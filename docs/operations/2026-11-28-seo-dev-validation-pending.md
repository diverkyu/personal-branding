# SEO 메뉴 순서 변경과 개발 DB 검증 준비

사용자 요청: 콘텐츠를 SEO보다 우선 배치하고 개발 DB에서 점검 일지 CRUD·상태 전이를 실제 시험한다. 운영 배포는 하지 않는다.

- 메뉴 순서: 홈 → 콘텐츠 → SEO 현황 → 운영 → 자산 → 사이트 → 시스템. 모바일 SEO 접기 메뉴도 같은 DOM 순서로 배치한다. 미리보기 HTML을 갱신했다.
- 기존 화면 렌더 시험 2개 통과, 타입·린트 통과, 24개 반응형 캡처 가로 넘침 없음.
- 현재 app에는 `.env.example`만 있고 실행 환경에도 DATABASE_URL/인증 설정이 없다. 개발 DB 연결 파일 위치를 사용자에게 요청했다. 운영 자격 증명을 대신 사용하지 않았다.
- 실제 Neon CRUD 및 DB 마이그레이션은 **미실행/연결 정보 대기**다. 기존 PGlite 시험을 실제 Neon 검증으로 보고하지 않는다.

## 연결 정보를 받은 뒤 수행할 순서

1. 사용자가 알려준 파일이 Neon dev 브랜치용인지 확인한다. 연결 문자열은 출력하지 않는다. 대상 확인 없이 migrate를 실행하지 않는다.
2. `app/.env.local`에 개발용 DATABASE_URL, BETTER_AUTH_SECRET과 로컬 SITE_URL을 구성한다. `SITE_INDEXING=off`로 유지한다. 인증 값은 사용자 로컬 시크릿으로만 다룬다.
3. `npm run db:status`로 누락 확인 → dev에 `npm run db:migrate` → status 재확인.
4. dev 대상 확인 후에만 `SEO_TEST_DB_BRANCH=dev`를 프로세스에 설정하고 `npm run seo:dev-smoke`를 실행한다. 이 표시는 dev 확인을 기록하는 안전장치이며 Neon 브랜치 자체를 자동 판별하지는 않는다.
5. 검증 명령은 가상 일지 하나를 등록·재조회·수정하고 잘못된 상태 전이/낡은 버전을 거부하는지 확인한다. 조치 필요→수정 완료→재검사 대기→추가 조치→수정 완료→재검사 대기→해결 완료, 삭제 확인과 소프트 삭제까지 검사한다. 실행별 고유 actor·제목으로 만든 시험 행/활동 기록만 finally에서 정리한다.
6. Next 개발 서버를 localhost의 별도 포트에 띄운다. 사용자가 개발 관리자 계정으로 로그인·2차 인증 후 화면 CRUD를 확인한다. 현재 3180은 저장 불가 정적 미리보기이며 이를 실DB 앱으로 표시하지 않는다.

`npm run seo:dev-smoke`는 자격 증명·dev 확인 플래그가 없는 경우 접속 전에 중단되는 것을 확인했다. 실제 DB 시험 통과는 아직 아니다. 신규 명령에 의존성 추가는 없다.
